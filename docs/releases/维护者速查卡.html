① 三层架构与四条铁则入口 → 调度 → 执行

入口层 tweak / normal / strict

薄编排技能，只声明档位，不代做任务判定与阶段衔接。命令层（/psfl:*）同样只做「选择 + 路由」，不产任何产物。

调度层 intake

执行层唯一入口。Step 1 恢复分发（在途优先）→ Step 2 入口粗判档 → Step 3 任务初始化（仅零在途）→ Step 4 转交。六出口：resume / handover / create / select / resolve-drafts / block。

执行层 阶段技能

specify → plan → design(可选) → tasks → build → verify → ship。阶段技能不得互相调用、不得直接调 intake；出口经 state next 推进游标。retro 是调度层唯一豁免：由用户直接触发，不需 task_id。

铁则：档位升降唯一位置 = specify 出口，过即冻结，其余阶段纯按 skill 字段转交；intake 复核只升不降；上游已给 task_id 时跳过枚举（机器交接免提问）。

⑤ state.yaml 写入纪律task-state-entry.sh 是唯一写入口

写什么

  • 阶段推进：complete-phase，--next-phase 可省——缺省由 nextPhaseForMode 按档位派生（plan→design/tasks 二分支仍显式传）
  • 游标语义：出口把游标设成「接下来要执行的阶段」，phase 即待执行阶段，与技能同名映射
  • 勾选同步：set-checkbox 同锁内写 tasks.md + runtime.build 计数

别写什么

  • 禁止直写 yaml 块；worktree 块的 appendFile 是全仓唯一绕过处，重复顶层键会让 yaml 库直接抛错、该文件此后全挂
  • runtime.propose.* 是孤儿段——propose 已改名 plan，正确路径 runtime.plan.*
  • runtime.build.pause_reason 等技能自造字段未登记类型，用前先查 state.example.yaml
⑥ CLI 速查polaris --help 仅列这些；hooks 运行时命令走 polaris-flow
命令用途 / 要点
polaris init初始化工作流 + Harness 环境；Superpowers 依赖 GitHub——不通时用 POLARIS_GITHUB_MIRROR 镜像或 POLARIS_SUPERPOWERS_PATH 本地目录
polaris status当前 change 与工作流状态
polaris dashboard本地工作台，API 与前端同端口；--api-only 供前端 HMR
polaris doctor诊断环境、schema 与 skill 安装状态
polaris update三层范围可单选：program（本体）/ assets（skills·commands·agents·rules·hooks，按指纹跳过）/ deps（openspec·superpowers·codegraph）。选项 --only --skip --force --prune --lang --scope --json；例：update --only skills,commands
polaris uninstall三层范围可单选：assets（默认，Polaris 自有资产）/ deps（openspec·codegraph）/ program（全局软件）。选项 --targets --keep-data --yes --dry-run --json；删除前列出并确认
