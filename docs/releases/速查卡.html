③ 5 个不要 & 何时换通道

✕ 最常犯的错

  • 需求说不清就开工 → 至少「做什么 + 对哪个对象 + 2 项细节」
  • 提示新开会话还硬续 → 丢上下文，照做
  • 嫌确认多想跳过 → 便宜时确认 比改完 20 个文件返工划算
  • 半路变复杂还硬扛 → 听提示切 normal / sdd
  • 想让评估往低判 → 宁严勿松，只升不降

▸ 何时换通道

  • 一眼就是小改动 → 直达 /psfl:coding:tweak
  • 线上告警 → 直达 /psfl:maintance:hotfix，先保现场
  • 根因不明 / 跨 3+ 模块 / 表结构 / API 破坏 → 退回 normal
  • 只想评现成文档 / 原型 / 用例 → review 类只出报告不阻断
④ 硬纪律（不可破 · 速记）
类别硬规则
命令名Claude Code / Trae 用 : 分隔；Cursor 换成 -（/psfl-coding-normal），词不变
判档拿不准一律 /psfl:flow；复杂度评估只升不降，判低了不能调
开工门槛「做什么 + 对哪个对象 + ≥2 项细节」，缺了不放行
确认明确整体确认才算数；「差不多」「可以吧」、沉默一律不算
推进每阶段停一次等你确认，这是设计如此；中断了输入当前命令名即可续跑
发布发布 / 灰度 / 回滚始终由人执行，AI 只负责把该确认的问你
⑤ 标准开场模板（贴给 AI 即可）
用 /psfl:flow。需求：[一句话说清做什么 + 对哪个对象 + 关键细节]。 材料：[PRD 路径 / 设计稿 / 目标代码路径，没有就删掉这行]。 按流程走：先澄清 → 自动评估复杂度判档 → 把评分依据给我看 → 再开工。
跨平台提醒：Cursor 侧把命令里的 : 全换成 -。开发类没需求不放行——这是防止产出和你的意图错位。
