# Polaris Dashboard 全局布局框架定义
## 1. 框架概述
Polaris Dashboard 全局布局框架是基于预设设计系统（色彩、字体、间距、圆角等）构建的统一视觉与交互架构，核心目标是为整个 Dashboard 提供标准化的页面结构、响应式适配逻辑和交互一致性，覆盖从页面外壳到组件层级的布局规则，确保跨页面、跨终端的体验统一。

框架以「固定上下栏 + 自适应内容区」的 App Shell 为核心骨架，结合模块化的页面布局模式、明确的响应式断点和深度层级规则，支撑首页、项目管理、任务管理、配置管理、环境检测等所有核心页面的布局实现。

## 2. 核心架构（App Shell）
### 2.1 整体结构
采用垂直方向的 Flex 布局作为全局外壳基础，满足「全屏可视区 + 固定上下栏 + 中间内容滚动」的核心交互需求，核心 CSS 定义如下：
```css
.app-shell {
  display: flex;
  flex-direction: column;
  height: 100vh;
  overflow: hidden;
  background: var(--bg); /* 主背景色 #121212 */
}
```
结构分层如下：
```
┌──────────────────────────────────────────────────┐
│  TopNavbar（固定高度 48px）                        │
├──────────────────────────────────────────────────┤
│  MainContent（flex: 1，垂直滚动）                  │
├──────────────────────────────────────────────────┤
│  BottomStatusBar（固定高度 32px）                 │
└──────────────────────────────────────────────────┘
```

### 2.2 布局分层职责
| 分层           | 高度   | 背景色       | 核心样式/职责                                                                 |
|----------------|--------|--------------|------------------------------------------------------------------------------|
| TopNavbar      | 48px   | --bg-sidebar | 底部带边框；承载 Logo、项目标签、导航按钮组；固定在视口顶部，不随内容滚动     |
| MainContent    | 自适应 | --bg         | flex: 1；overflow-y: auto；承载所有页面级内容；各子页面在此区域内实现差异化布局 |
| BottomStatusBar| 32px   | --bg-sidebar | 顶部带边框；三等分布局（左/中/右）；承载全局状态提示；固定在视口底部           |

## 3. 核心布局组件规范
### 3.1 顶部导航栏（TopNavbar）
#### 3.1.1 内容结构
```
┌──────────────────────────────────────────────────┐
│ >_ polaris [项目标签区]               首页 任务 配置 │
└──────────────────────────────────────────────────┘
```
- 左侧：品牌标识（`>_ polaris`），使用 `--font-mono` 字体、`--primary` 色值，字重 700，字号 14px；
- 中间：项目标签区（仅任务页面显示，其余页面留空但保留宽度），模拟浏览器标签样式；
- 右侧：导航按钮组（`<a>` 标签），`padding: 6px 16px`，`border-radius: var(--radius)`；

#### 3.1.2 交互规则
- 按钮 hover：`background: rgba(34, 197, 94, 0.1)`，文字亮度提升；
- 按钮 active：`background: rgba(34, 197, 94, 0.15)`，文字色为 `--primary`；
- 所有交互过渡：`0.15s ease`。

### 3.2 底部状态栏（BottomStatusBar）
- 字体规范：11px 字号，`--text-muted` 色值（#9CA3AF）；
- 布局规则：水平三等分，当前为占位态，后续可扩展全局状态（如系统版本、网络状态、通知数）；
- 视觉边界：顶部 1px 边框，与 `--border` 色值一致（#333333）。

### 3.3 主内容区（MainContent）
作为所有页面内容的容器，核心规则：
- 基础样式：`padding: var(--space-xl)`（24px），确保内容与边缘有统一间距；
- 内容对齐：多数页面（首页、项目管理、环境检测）采用「水平居中 + 最大宽度限制」，避免大屏下内容过度拉伸：
  - 首页/环境检测：最大宽度 900px；
  - 项目管理：最大宽度 1000px；
- 滚动规则：仅垂直方向滚动（`overflow-y: auto`），水平方向禁止溢出（特殊场景如步骤进度组件可横向滚动）。

## 4. 页面级布局模式
主内容区内的子页面采用差异化布局模式，核心分类如下：

### 4.1 网格卡片布局（首页）
- 核心结构：4 列 Grid 布局，`gap: var(--space-lg)`（16px）；
- 响应式调整：移动端（<768px）切换为 2 列；
- 内容载体：统计卡片（.stat-card），居中布局，承载核心数值与标签。

### 4.2 表格布局（项目管理页）
- 核心结构：全屏宽度（最大 1000px）的表格，包含「别名/路径/添加时间/操作」列；
- 视觉规则：表头 12px 大写文字，`letter-spacing: 0.5px`；行 hover 背景为 `rgba(34, 197, 94, 0.05)`；
- 交互规则：「删除」按钮使用 `--error` 色值（#ef4444），符合语义色约定。

### 4.3 双栏布局（任务管理/配置管理页）
| 页面         | 左侧栏宽度 | 右侧栏规则               | 核心内容                     |
|--------------|------------|--------------------------|------------------------------|
| 任务管理页   | 280px      | flex: 1                  | 步骤进度条、阶段卡片、项目信息 |
| 配置管理页   | 200px      | flex: 1                  | 路径标签、保存按钮、代码编辑区 |
- 分割规则：两栏之间保留 `var(--space-lg)`（16px）间距；
- 响应式：小屏下可折叠左侧栏为抽屉式，优先展示右侧核心内容。

### 4.4 摘要+清单布局（环境检测页）
- 摘要区：3 个语义色卡片（错误/警告/通过），分别对应 `--error`/`--warning`/`--success`；
- 清单区：每项左侧 3px 状态色边框 + 图标 + 名称 + 描述，视觉上强化状态区分。

## 5. 响应式布局规则
基于屏幕断点划分布局调整逻辑，确保多终端适配：

| 断点范围       | 核心布局调整                                                                 |
|----------------|------------------------------------------------------------------------------|
| >=1024px（大屏） | 默认布局：4 列统计卡片、完整双栏宽度、步骤进度组件全尺寸展示                 |
| 768px~1023px（中屏） | 统计卡片 4→2 列；步骤进度分组 min-width 缩小为 120px，padding/gap 收紧       |
| <768px（小屏/移动端） | 统计卡片保持 2 列；表格字号缩小；双栏布局切换为「抽屉式左侧栏 + 全屏右侧栏」 |

## 6. 布局与组件的融合规范
全局布局框架需适配核心组件的视觉与交互规则，确保整体一致性：
### 6.1 间距与圆角
所有布局内组件均遵循预设间距阶梯（4px 基准）和圆角阶梯：
- 间距：组件内/组件间优先使用 `--space-sm`（8px）、`--space-md`（12px）、`--space-lg`（16px）；
- 圆角：卡片/面板使用 `--radius-lg`（8px），按钮/输入框使用 `--radius`（6px），小元素使用 `--radius-sm`（4px）。

### 6.2 组件视觉适配
- 卡片组件：背景 `--surface`（#1E1E1E），hover 时边框变为 `--primary` + 发光效果（`--primary-glow`）；
- 进度类组件：进度条颜色随进度动态变化（<50% 用 `--error`，50-99% 用 `--warning`，100% 用 `--success`）；
- 步骤进度组件：大屏下完整展示，中小屏下横向滚动，分组尺寸自适应收缩。

## 7. 深度层级（z-index）
为避免布局元素层级冲突，全局统一深度规则：
| z-index 值 | 适用元素               | 核心用途                     |
|------------|------------------------|------------------------------|
| 100        | TopNavbar              | 确保导航栏始终在内容之上     |
| 200        | 预留覆盖层             | 如临时遮罩、加载层等         |
| 300        | 模态框/下拉菜单        | 最高层级，覆盖所有布局元素   |

## 8. 交互与动效适配
### 8.1 交互规则
所有布局内可点击元素（导航按钮、卡片、文件树项）遵循统一交互逻辑：
- 过渡时长：`0.15s ease`；
- hover 态：背景/边框趋近 `--primary`，文字亮度提升；
- active 态：背景/边框强化为 `--primary-glow-strong`，文字色为 `--primary`。

### 8.2 动效规则
- 布局相关动效（如进度条填充、步骤状态切换）遵循预设时长与缓动曲线；
- 适配系统偏好：当 `prefers-reduced-motion: reduce` 时，关闭所有非必要动画（如 shimmer、neon-pulse）。

## 9. 开发规范
全局布局框架的代码实现需遵循以下规则：
- 技术栈：Vue 3 CDN 模式（ESM import），无构建步骤；
- CSS 规范：使用原生 CSS 变量（与设计系统一致），BEM 风格类名；
- 状态管理：全局状态通过 `reactive()` 在 App setup 中统一管理；
- 路由适配：页面切换通过 `computed` + hash 路由实现，布局外壳保持不变；
- 依赖约束：不引入额外 npm 依赖，仅使用原生 HTML/CSS/JS + Vue 3 核心能力。
