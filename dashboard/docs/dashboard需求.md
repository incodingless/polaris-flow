# Dashboard需求
## 一、页面基础信息
1. **产品定位**：OpenSpec 配套服务端工作台，提供 WebUI / CLI 双入口（顶部右上角：OpenSpec WebUI v0.3.5、OpenSpec CLI v1.4.1）
2. **语言规范**：界面正文使用中文；规范级强制关键字使用英文 `SHALL/MUST`
3. **整体用途**：管理 OpenSpec 领域规范、变更提案、任务校验、迭代记录的研发管控工作台

---
## 二、顶部全局核心指标卡片（4个横向数据块）
### 1. 活动变更

- 数值：`2`
- 释义：**当前正在进行中的变更项数量**
- 作用：快速知晓当前有多少未收尾的规范/模块变更在推进

### 2. 归档
- 数值：`3`
- 释义：**已完成归档、可回溯查看的历史变更**
- 作用：统计已落地闭环的变更总量

### 3. 参考规范
- 数值：`12`
- 释义：系统内存储、可复用的业务规范文档总数
- 作用：展示规范资产池规模

### 4. 任务
- 数值：`0% / 0/40`
- 释义：全局任务完成进度：总任务40个，当前完成0，整体进度0%
- 作用：宏观把控所有变更拆解后的执行任务进度

---
## 三、Active Changes 活动变更模块
### 1. 变更条目列表（每条代表一个独立变更工单）
每条变更卡片统一结构：
1. **标题**：模块英文名 + 中文名称（例：`universal-logging 通用日志`）

2. **标签分类**：

   - Proposal 提案、Design 设计、Other X 其他附属子项数量

     根据变更的进度，依次列出当前变更已经完成的阶段

3. **元数据**：更新时间、`spec deltas`（规范差异条数）、任务统计（已完成/总任务）

4. **Progress 进度**：单条变更独立完成百分比，计算方法为：当前已经完成的变更阶段数量/所有变更阶段数量

#### 示例两条变更
1. universal-logging 通用日志
   - 4条规范差异，0任务完成/0总任务，进度0%
2. organization-management 组织管理
   - 2条规范差异，0任务完成/40总任务，进度0%

---
## 四、Recent Activity 最近活动模块
### 标题说明
> 工作区中最新的变更和规范更新
### 布局
网格卡片布局，**按时间倒序**展示全平台所有模块的更新记录，每条卡片包含：
1. 模块名称（中英双语）
2. 更新时间戳
3. 辅助数据：规范数量、进度比值（例 4 / 0/0、4 / 21/21）
### 展示内容

按时间由近到远获取近12个变更

### 作用
- 快速追溯全平台规范、模块的更新时序
- 直观查看每个模块的迭代频次、完成状态
- 快速定位近期改动的业务域
