## 修复：第 1 级选完后第 2 级弹不出来（实测反馈）

用户实测反馈「选完第 1 级就无法正确弹出第 2 级」。两个根因，已修：

1. **结构问题（主因）**：两级询问都写在 `## 第一步` 的 `###` 子标题下，紧邻的 `## 第二步` 就是
   「按选择加载技能」。模型拿到第 1 级答案后顺着一级标题往下走，直接进了加载技能，第 2 级被跳过。
   → 修法：把两级提升为**平级的一级步骤**，全文改为 第一步(类别) → 第二步(具体功能) →
   第三步(查表加载技能) → 第四步(交给技能执行)。
2. **第 2 级缺完整调用体**：原本每组只给 `{ "label": ..., "description": ... }` 碎片，没有
   `question` / `header` / `multiSelect`，模型拼不出工具调用就退化成纯文本罗列。
   → 修法：四组各给一份**完整可原样复制的 `AskUserQuestion` JSON**。

### 写多轮 AskUserQuestion 类命令的通用经验（可复用）

- 多轮询问必须各自占一个**一级标题**，不要塞进同一节的 `###` 子标题里，否则模型会按标题层级
  直接跳到下一个「动作型」步骤。
- 每一轮的示例都给**完整工具调用 payload**，不要只给 options 数组片段。
- 加一条「执行状态」小节（如 `已选类别` / `已选功能`），要求每步结束回查，缺值就不许往下走。
- HARD-STOP 里显式写死「禁止在第 N 级拿到答案后直接跳去做动作」和「禁止用纯文本罗列代替工具调用」。

## 新增第三步：收集附加上下文

用户实测反馈「选完功能后没机会附加上下文文件/告诉技能要读哪些文档」。在「选具体功能」与
「加载技能」之间插入 `## 第三步：收集附加上下文`：

- 3.1 用 `AskUserQuestion` 三选一：附加文件/目录 / 补充文字说明 / 直接开始
- 3.2 选前两项则**停下来等具体内容**（路径要逐个校验存在性，报错须指明哪几个路径有问题）；
  选「直接开始」则 `附加上下文 = 无`
- 3.3 交接口径：技能须在自身流程开始前先读完上下文；读取失败要回报用户，不得静默跳过；
  产物与上下文冲突时以上下文优先
- 执行状态扩为三个：`已选类别` / `已选功能` / `附加上下文`（`待收集`/`无`/清单）
- 顺带：前置依赖检查改为先看 `附加上下文`，用户附加的材料若已覆盖所需前置即视为满足
- 后续步骤顺延为 第四步(加载技能) → 第五步(交给技能执行)

### 为什么命令不能像技能那样引用 `./policies/xxx.md`

- 共享 policies **只注入叶技能的 `policies/`**（`install/skills.ts` Step 3），插件根没有 `policies/`，
  所以命令拿不到 `$PLUGIN_ROOT/policies/ask-question-react.md`

  `policies/ask-question-react.md` 会变成一条 `/polaris:policies:ask-question-react` 垃圾命令
- → 结论：命令内联精简注册表是唯一安全解；已在文件内注明「若与共享策略冲突以策略文件为准」
