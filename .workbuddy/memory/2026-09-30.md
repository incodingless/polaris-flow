# 2026-09-30

## polaris update 命令现状探查与改造方案（未实施）

### 现状（代码定位）
- `src/commands/update.ts`：`runUpdate` 只做「重拷 Polaris bundled 资产」。
  流程 = 解析 path/scope(默认 project)/lang(**默认 en**) → `findInstalledPlatforms`
  （`detectPlatforms` ∩ 目标 skills 目录含 `polaris*`）→ 读 `assets/manifest.json`.version
  与 `.polaris/installed-version` 比对 → 不等或 `--force` 才逐平台调
  `installPolarisForPlatform` → 写回 `installed-version`。
- 三层「更新」里只覆盖了中间一层，且覆盖得不完整。

### 已确认的真实缺陷（有代码证据）
1. **默认 lang=en 造成假成功**：`assets/en/skills/` 只有 1 个 `.gitkeep`（实测 0 技能），
   zh 有 188 个文件。`polaris update` 不带 `--lang zh` 时 skills copied=0，
   但仍写 `installed-version = manifest.version` → 之后即使补 `--lang zh`
   也会因版本相等而直接 return（除非 `--force`）。这是「不能更新技能」的直接原因之一。
2. **版本门控失效**：`manifest.version`(0.1.0) 与 `package.json`(0.1.1) 已漂移；
   资产内容变动不伴随 manifest.version 递增 → update 永久跳过。
3. **无 prune**：删除/改名的技能（如已移除的 `coding/refactor`）在目标目录残留；
   `copyIfMissing` + `overwrite=false` 全线只增不减。
4. **hooks 只有 overwrite 才刷新**：非 force 路径走 merge，
   模板中已删除的事件组/托管 command 不会被清理。
5. **不读 `.polaris/config.yaml`**：lang / scope / platforms 全靠 CLI 参数，
   与 init 写入的配置脱钩；`skills-lock.json` 由 init 写入但**无人读取**。

### 方案要点（待用户拍板）
- 三层范围：`program`（npm 包自更新）/ `assets`（skills·commands·agents·rules·hooks）/
  `deps`（openspec·superpowers·codegraph），CLI 加 `--only` / `--skip`。
  注意 `--scope` 已被 install scope 占用，范围参数不能复用该名。
- 程序自更新：探包管理器后 `npm i -g @polaris/polaris-flow@latest`；
  npx 场景（`_npx` 缓存）只提示不装全局，避免副作用。
- assets 层：给 `installPolarisForPlatform` 加可选 `only?: PolarisAssetKind[]`
  （init 不传 → 零行为变化），update 侧按 only 过滤；门控改内容比对；
  新增 `--prune` 清「polaris 托管路径下但已不在源清单」的文件。
- deps 层复用现有安装器：`installOpenSpec`（内置 `@latest` 升级）、
  `installSuperpowersForPlatforms`、`installCodegraph`。
- i18n 已有 `updatingNpmPackage` / `npmPackageUpdated` / `summaryNpm` /
  `summaryCodegraph` 等**未被引用**的存量键，可直接启用而非新造。

### 待确认
1. 程序自更新通道（调包管理器 / 更醒目的提示）
2. 范围粒度（3 组 / 8 项细粒度 / 并存）
3. `--prune` 做不做（风险：会删用户在托管路径下自建的文件）
4. 是否废弃 `manifest.version` 版本门控

## polaris update 三层改造（已实施，**未验证**）

### 用户拍板
- D1 = B：调包管理器做程序自更新（探测 npm/pnpm/yarn/bun），npx/bunx 场景降级为只提示
- D2 = 并存：组名（program/assets/deps/all）+ 成员名（5 类资产 + 3 个依赖）
- D3 = 做 prune，默认关，需显式 `--prune`
- D4 = 用 sourceHash 取代 manifest.version 门控
- 附带修 init `selectLanguage` 在 `--yes` 下返回 `'en'` 的坑

### 落地形态
- 新增 `src/core/install/types.ts`：`PolarisAssetKind` / `POLARIS_ASSET_KINDS` / `CopyStats{copied,skipped,files}`
- 新增 `src/core/update/scope.ts`：`resolveUpdatePlan`（组展开、`--only`/`--skip` 互斥、未知项报错）
- 新增 `src/core/update/fingerprint.ts`：按平台按类别 sha256（源内容 + 布局/config 改写输入）
- 新增 `src/core/update/prune.ts`：只清 skills / commands 的独占命名空间；agents / rules / hooks 刻意不清
- 新增 `src/core/deps/self-update.ts`：`detectPackageManager` / `isTransientRunnerInvocation` / `updatePolarisProgram`
- `install.ts`：`installPolarisForPlatform` 加第 7 参 `options { only, overwriteHooks }`，新增 `installedFiles`
- `lock.ts`：`LockFile.assets`（指纹）+ `updatedAt`；新增 `readLockFile` / `saveLockFile` / `getSkillsLockPath`
- `hooks.ts`：`mergeHooksMaps` 改为合并前剔除**所有**事件的托管 command（修陈旧残留）
- `codegraph.ts`：`ensureCodegraphCli(upgrade)` / `installCodegraph(upgradeCli)`，已有索引时不重建
- `commands/update.ts` 重写；CLI 加 `--only` / `--skip` / `--prune`；删除 `.polaris/installed-version` 与 16 个死 i18n 键
- 新增测试：`update-scope` / `update-fingerprint` / `update-prune` / `update`

### 关键语义变化
- 非 `--force` 时也以 overwrite=true 重写命中类别（原实现只新增、从不改写既有文件）
- update 的 lang / scope 优先读 `.polaris/config.yaml`
- 执行顺序「先资产、后程序」
