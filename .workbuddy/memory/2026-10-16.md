## build 并行派发可行性核实（/opsx:apply 能力探查）

- 用户问：build 单 subagent 串行写代码慢，tasks 规划时能否按依赖/关联分组、不同组由不同 subagent 并行执行。
- 核实结论（本机 openspec v1.14.2 @ `/opt/homebrew/lib/node_modules/@fission-ai/openspec`）：
  - `openspec apply` 子命令**不存在**；`/opsx:apply` 实际 = `openspec instructions apply`（**指令生成器**，非执行器）。
  - CLI 选项仅 `--change/--schema/--json/--store`，**无 task 级范围参数**。
  - 进度追踪 = `dist/commands/workflow/instructions.js` 的 `parseTaskLines`/`toTaskItems`（L226-260）解析 tasks.md 的 checkbox（`- [x]`=done，其余含 `- [~]` 都算未完成）；**不解析 `## 组` 标题**，组语义 apply 完全不消费。
  - 默认 instruction 文案（schema.yaml L270-272）=「Read context files, work through pending tasks, mark complete as you go」→ 全量剩余串行。
  - `apply.tracks` 注释支持 glob（L414），但 spec-driven schema `tracks: tasks.md` 单文件；polaris-flow 约束「唯一实施计划 = 单份 tasks.md」（tasks HARD-GATE L25）。
- 结论：**并行地基不在 apply 命令里**。要并行必须动 tasks 产出 + build 执行模型，且撞两个既有硬约束（build HARD-GATE L13「禁止 apply 外写实现」+ implementer-prompt「唯一动作 = /opsx:apply」）。
- 方案三选一已给用户（① 只落依赖分组标注不并行 / ② 改 build 执行模型绕开 apply 全量 / ③ 改 schema 切多 tasks 文件），推荐先 ① + 测「可并行窗口」。**未改任何资产**，待用户裁定方向。
