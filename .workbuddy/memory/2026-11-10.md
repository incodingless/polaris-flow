## Dashboard 阶段写入锁归属修复（`advanceTaskPhase` 超时）
- 根因：`src/dashboard/api/tasks.ts` 的 `advanceTaskPhase` 调 `runTaskStateEntry` 时漏传 `repoRoot`，原语 `resolveRepoRoot(undefined)` 回退到 `git rev-parse`（CLI 进程 cwd 的 git 仓），`task-state-<id>.lock` 因此落到真实仓而非目标项目根。全量 vitest 多 worker 抢同一把锁 → 自旋等待 5s stale → `dashboard-write.test.ts` 两例 5000ms 超时，并在真实仓留下 stale 锁。`setTaskCheckbox` 本来就传 `repoRoot`，两者不对称是定位线索。
- 修复：`advanceTaskPhase` 显式传 `repoRoot: projectRoot` + `taskId`；`dashboard-write.test.ts` 的「写完不残留锁文件」补断言 `.polaris/.locks/` 必须存在于目标项目根（原断言只查「文件不存在」，锁写到别的仓库时恒通过 = 假阳性）。
- **约定**：凡 `runTaskStateEntry` 写 op，调用方必须显式传 `repoRoot`，不要依赖 `git rev-parse` 回退；多项目面板下锁目录必须随目标项目走。`enter-phase` 在 `runWriteOp` 里不使用 `repoRoot`（只有 `set-checkbox` 用），所以补传只改锁目录、不改写入行为。
- 验证：dashboard-write 单文件 25/25；原两个超时用例定向 2/2（486ms）；`--maxWorkers=2` 全量 62/63 文件、577/579 用例通过。mtime 前后比对证明修复后测试不再触碰真实仓锁。

## dev.sh 菜单 99 同步技能超时可跳过继续
- 需求：99（2→4→8→5）在同步附带技能超时时询问，选「是」则忽略同步继续发布+打包。用户裁定两点：跳过同步后继续跑完 8+5（不是只打离线包）；降级按退出码分档。
- **`sync-bundled-skills.mjs` 退出码语义（--update 模式）**：`0` 最新/已升级；`2` 查询上游失败（含 `ls-remote` 60s 超时），脚本在任何写操作前 `process.exit(2)` 并声明「未做任何修改」→ **唯一安全的降级点**；`1`（--update 下）只能是升级阶段未捕获异常。
- **半成品风险**：升级循环里 `replaceVendorSkill` 逐个替换 vendor（:364-378），`fs.writeFileSync(SPEC_FILE, tsSource)` 在循环结束后才落盘（:380-381）。中途 clone/fetch 超时 → 部分技能 vendor 新版 + TS 钉值旧版；若此时跳过继续，`publish.sh` 发旧钉值 npm 包、`package.sh` 打新版 vendor 进离线包，用户装机按钉值重拉即对不上。故退出码 1 一律中止 + 提示核对钉值，**不提供跳过**。
- 结论：**只改 `devops/dev.sh`，不动 sync 脚本**。退出码 2 已是「未做修改」的充分信号，不需要再造超时专用码（符合 AGENTS.md「最简实现」）。`read` 遇 EOF 默认 N 中止。
- 验证：`bash -n` + `dev.sh list` + 临时 harness（stub `node`/`bash`/`precheck_publish`，6 个场景全 PASS：node=0 走完、node=2 选 y 继续到发布、选 n 中止、EOF 中止、node=1 不询问直接中止）。`test/` 下无 dev.sh / sync 相关既有测试。
- Changelog 追加到 0.9.2 的 `### Changed`（main=0.9.1，0.9.2 条目已存在且未发布），未 bump 版本、未动 package.json。工作区其余 15 个改动属其它任务，未碰。

## 离线包附带技能缺版本标记（archify）修复
- 现象：`devops/vendor/bundled-skills/archify/` 没有 `.polaris-bundled-ref`（2026-10-22 手工拷入），`diagram-design/` 有（2026-11-09 sync 写的）；已生成的 `release-0.9.1` 离线包同样缺。`isBundledSkillPresent`（`bundled-skills.ts:101-123`）把无标记副本判为「缺失」→ 离线安装时白跑一次联网重拉 + 打印 `Diagram failed`（`init.ts:398-409` 已自带「本地已有副本仍会安装」提示，**是假告警，不是装不上**）。
- 根因：`sync-bundled-skills.mjs` 的 `replaceVendorSkill` 只在 `for (const row of outdated)` 里写标记，没新版的技能永远补不上；`package.sh` 又原样 `cp -R` vendor，缺标记一路带进交付物。
- **修复落点选 `package.sh`（交付物最后一道），不选 sync、不改运行时判定**：
  - 不改运行时：`skills-install.test.ts:469-483` 明确「缺标记按缺失处理，宁可重拉一次」是设计意图，放宽判定属回退设计。
  - 不选 sync：`--update` 只在有新版时写标记，且 99 里退出码 2 被「跳过同步继续打包」降级时 sync 根本没成功跑完，覆盖不到降级路径。
  - `package.sh` 每次打包必跑，天然覆盖两条路径。
- 实现：拷贝 bundled-skills 后，`node - <<'NODE'` 读 `src/core/integrations/bundled-skills.ts` 的 `BUNDLED_SKILL_SPECS`，按 `commit ?? version` 给**缺标记**的技能写 `.polaris-bundled-ref`。**只补缺失、不覆盖已有值**——标记与钉值不一致时应由运行时重拉纠正，打包不该抹平（否则会掩盖上一轮说的 sync 半成品不一致）。TS 解析不到任何 spec 直接抛错让 `set -e` 中断，防复发。
- 同时给本机 `devops/vendor/bundled-skills/archify/.polaris-bundled-ref` 写入 `3.2.0`（gitignored、不持久，只让本机状态自洽）。
- 验证：`bash -n devops/package.sh` OK；抽出 heredoc 脚本用真实 TS + 真实 vendor 副本隔离跑 → archify 补为 3.2.0 / diagram-design 已有 SHA 未被覆盖 / 二次执行幂等无输出；`npx vitest run test/ts/skills-install.test.ts` 19/19。**未跑完整 `package.sh`**：它会 `npm view` 内网 Nexus 拉 npm 组件，没必要为这段纯本地逻辑引入联网与 vendor 缓存副作用。
