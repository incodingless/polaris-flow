## Dashboard 阶段写入锁归属修复（`advanceTaskPhase` 超时）
- 根因：`src/dashboard/api/tasks.ts` 的 `advanceTaskPhase` 调 `runTaskStateEntry` 时漏传 `repoRoot`，原语 `resolveRepoRoot(undefined)` 回退到 `git rev-parse`（CLI 进程 cwd 的 git 仓），`task-state-<id>.lock` 因此落到真实仓而非目标项目根。全量 vitest 多 worker 抢同一把锁 → 自旋等待 5s stale → `dashboard-write.test.ts` 两例 5000ms 超时，并在真实仓留下 stale 锁。`setTaskCheckbox` 本来就传 `repoRoot`，两者不对称是定位线索。

## dev.sh 菜单 99 同步技能超时可跳过继续
- 需求：99（2→4→8→5）在同步附带技能超时时询问，选「是」则忽略同步继续发布+打包。用户裁定两点：跳过同步后继续跑完 8+5（不是只打离线包）；降级按退出码分档。
- **`sync-bundled-skills.mjs` 退出码语义（--update 模式）**：`0` 最新/已升级；`2` 查询上游失败（含 `ls-remote` 60s 超时），脚本在任何写操作前 `process.exit(2)` 并声明「未做任何修改」→ **唯一安全的降级点**；`1`（--update 下）只能是升级阶段未捕获异常。
- **半成品风险**：升级循环里 `replaceVendorSkill` 逐个替换 vendor（:364-378），`fs.writeFileSync(SPEC_FILE, tsSource)` 在循环结束后才落盘（:380-381）。中途 clone/fetch 超时 → 部分技能 vendor 新版 + TS 钉值旧版；若此时跳过继续，`publish.sh` 发旧钉值 npm 包、`package.sh` 打新版 vendor 进离线包，用户装机按钉值重拉即对不上。故退出码 1 一律中止 + 提示核对钉值，**不提供跳过**。
- 结论：**只改 `devops/dev.sh`，不动 sync 脚本**。退出码 2 已是「未做修改」的充分信号，不需要再造超时专用码（符合 AGENTS.md「最简实现」）。`read` 遇 EOF 默认 N 中止。
- 验证：`bash -n` + `dev.sh list` + 临时 harness（stub `node`/`bash`/`precheck_publish`，6 个场景全 PASS：node=0 走完、node=2 选 y 继续到发布、选 n 中止、EOF 中止、node=1 不询问直接中止）。`test/` 下无 dev.sh / sync 相关既有测试。

## Trae / Trae-CN 命令布局定为 `namespaced-flat`（三段冒号在该宿主不可达）
- **实测规则（2026-11-10 IDE 命令菜单截图）**：Trae 菜单名由路径推导，**只把最后一级 `/` 变成 `:`，更早的 `/` 原样保留**。`psfl/flow.md` → `psfl:flow`；`psfl/coding/normal.md` → `psfl/coding:normal`。故 `/psfl:coding:normal`（两段冒号）不可达——要拼两段必须让目录名/文件名含 `:`，Windows 禁止。0.9.0 旧注释「不折叠 / → :」只对一半；上一轮「冲突点 3 是错误信息」的裁定被截图推翻。

- 连带：`layout.ts` / `prune.ts` / `uninstall.ts` / `fingerprint.ts` 都只判 `=== 'flat'`，第三值自动走 nested 分支，无需改代码；`prune` 与 `uninstall` 在 `namespaced-flat` 平台顺带清 0.9.1 留下的顶层 `psfl-*.md`（升级残留，否则两套触发名并存）。

## Trae 命令名方案再修正：`{{CMD_NS}}` 注入 name（⚠️ 推翻上节结论）
- ⚠️ **上节（namespaced-flat 连字符命令名）结论作废**：用户裁定「命令名 `/psfl:coding-normal`」方案错误。用户确认的宿主模型是 **Trae 命令名由 frontmatter 的 `command_prefix` + `name` 推导，`name` 可带 `:` 形成多段命名空间**；上节那段「路径只折叠最后一级 `/`、两段冒号不可达」的实测推导不再作为依据。
