## 故障：`npm publish` 到 Nexus 返回 E403（权限，不是认证/配置）
- 实测矩阵（凭据取自 `~/.npmrc` 的 `_auth`，解码后账号 = `npm_deployment`）：
  - 带凭据访问 `service/local/repositories` → **403**（不是 401）⇒ 凭据有效、Nexus 已识别身份，只是无权限。
  - 匿名 PUT `npm-hosted` → **401**；带凭据 PUT → **403**。
  - `npm publish` 日志：GET packument 403 → PUT 403，即读写都被拒。
- 结论：`.npmrc`/`--registry` 配置无误，缺 `npm_deployment` 对 `npm-hosted` 的 create/update 权限。
- 判据（复用价值高）：**401 = 未认证/凭据无效；403 = 已认证但无权限**。两者别混。
- 待用户执行的决定性验证：用 admin 账号对 hosted 发同一条 PUT —— 2xx ⇒ 纯权限问题（Nexus 2 UI：Security → Roles 勾 npm-hosted 的 browse/read/create/update → 分配给 npm_deployment）；403 ⇒ Nexus 2 npm hosted 不支持发布，改 Verdaccio。
- 文档：发布指南 A-5 的 E403 行原写 Nexus 3 权限名 `nx-repository-view-npm-*-add`（Nexus 2 里不存在），已改为 Nexus 2 口径 + 401/403 判据 + admin 对照测试。
- 附带：publish 日志有 `bin[polaris] script name was cleaned` 警告（npm 自动纠正 bin 字段），与本次失败无关。
- 后续：用户自行配好用户/角色/权限后再测 → 带凭据 PUT 返回 **201**（201 = 成功，不是错误），说明 Nexus 2 的 npm hosted **确实支持发布**，此前 403 纯属权限缺失。
- 闭环验证（已做，用废弃包）：`/tmp/npmprobe` 建 `polaris-flow-probe@0.0.1` → `npm publish --registry <hosted>` 成功（`+ polaris-flow-probe@0.0.1`）→ `npm view ... --registry <group>` 返回 `0.0.1` ⇒ **发布 + 聚合读取全通**。

## Nexus 3 长期认证（16:26，用户问「30 天要重登，能长期登录吗」）
- 结论：**能**。Nexus 3 对 npm 支持两种认证，`npm login` 只是其中一种：
  - `//host/repository/npm-hosted/:_authToken=NpmToken.xxx` —— `npm login --auth-type=legacy` 写入，**有有效期**。Pro 版可在 `Settings → Security → User Token` 配 1–999 天或关闭（官方文档：默认 30 天，3.69.0 起可改）；**Community 版没有该配置项**，故 OSS 上只能靠 Basic。

## doctor 误报 bash not found（20:59，已修）
- 现象：CentOS aarch64 上 `polaris doctor` 报 `bash: not found in PATH`，但 `bash --version` 正常。
- 根因：POSIX 命令探测全用外部 `which`（openspec.ts isCommandAvailable / detect.ts commandAvailable + resolveCommandPath 三处），CentOS 最小化安装默认不带 `which` 包 → execFileSync ENOENT → catch 后一律返回 false，所有命令全误报。git/openspec 未装是真，bash 是误报。
- 修复：POSIX 分支改 `execFileSync('sh', ['-c', 'command -v "$1"', 'sh', cmd])`（内建，零外部依赖）；Windows 保持 `where`。resolveCommandPath 用 stdout 首行取路径。
- 验证：build 通过；vitest 55 文件 514/514 通过。
- 待办：那台机器 git / openspec 是真缺失，需 `sudo yum install git` + `sudo npm install -g @fission-ai/openspec@latest`；修复要随下一版发布后才在那台机器生效。
- 关联：同批还发现 npm 发布永远剔除 `.gitignore` → `assets/shared/.gitignore` 不进包 → 用户项目 `.polaris/.gitignore` 从未生成（批1 待修）；EACCES 定向提示（批2 待裁）。
