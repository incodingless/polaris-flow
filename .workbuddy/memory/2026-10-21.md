## Nexus 内网分发落地（实测 + 脚本/文档改造）
- 用户 Nexus：`http://192.168.2.96:8081`，版本 **2.15.1-02**（Nexus 2，EOL）。仓库已建：`npm-group`（group）/ `npm-hosted`（hosted）/ `npmjs`（proxy）。
- 实测事实（勿再凭印象判断）：REST `/service/local/repositories` 里 npm 仓库的 `provider/format` 仍显示 maven2 —— Nexus 2 的 npm 支持是贴 maven provider 实现的，**不能靠该字段判断**；真实判据是按 npm 协议探路径：
  - `content/groups/npm-group/commander` → 200 且返回 npm 元数据 ✅
  - `content/repositories/npmjs/commander` → 200 ✅（proxy 可用）
  - `npm view commander|yaml --registry <group>` → 正常返回 ✅
  - hosted 根 `/` → 200（目录索引页）；`-/ping` → 404 HTML（Nexus 2 不实现 npm ping，不代表不可发布）
  - 对 hosted 发 `PUT /polaris-flow-probe` → **401（需认证）而非 405**，说明发布路由存在
- Nexus 2 认证口径：Basic，`.npmrc` 用 `//host/nexus/content/repositories/npm-hosted/:_auth=<base64(user:pass)>`；**没有** `npm login` / npm Bearer Token Realm（那是 Nexus 3）。
- 落盘改动：`install.sh` 默认 registry 固定为 npm-group（`NPM_REGISTRY` 仍可覆盖，分支简化为单条 `--registry`）；`.gitlab-ci.yml` 改为发布 npm-hosted + `NPM_AUTH`（base64 Basic），依赖安装走 group；安装手册/发布指南全部改 Nexus 口径（含 3 条发布后验证：hosted 有包 / group 能读到 / npm view 通）。
- 待办：**真实凭据的发布闭环未验证**（需 `npm publish` 一个测试包 → 从 group 装回）；GitLab Variables 配 `NPM_AUTH`；hosted 是否已加入 group 成员列表需在第 2 条验证时确认。

## 《发布操作指南》按通道重排（用户反馈"一头雾水"）
- 原因：旧版把两条通道交错叙述——零节讲 npm 准备、一节路线里混着"见第六节"指路、六节才讲 Nexus，读者须拼着看。
- 结构裁定（用户手定原则：一个通道一个完整流程）：① 开头通道对比表 + 明确「选一条走完，不混读」；② 共用前置（升版本/写 Changelog/自检/提交）单列一节气；③ 通道 A（Nexus）与通道 B（npmjs）各自内部同构：一次性准备 → 首次手动发布 → 后续发版(CI/手动) → 发布后验证 → 专属报错；④ 撤包处置合并在第四节、用"通道差异"列标注（公网 72h 限制 vs Nexus 无时限）；⑤ 双通道同时发布独立成第五节。
- 新增的两条通道差异事实：Nexus hosted 若开 Allow Redeploy，同版本重复发布是**覆盖**而非报错（版本号唯一性只在公网 npm 强约束）；通道 B 发布前必须 `npm config get registry`，否则被通道 A 的 `~/.npmrc` registry 带偏。

## 拓扑裁定：源码在 GitHub，分发走内网 Nexus（用户选"路线 1"）
- 硬约束：GitHub 托管 runner 在公网 → **路由不到** `192.168.2.96`，发 Nexus 只能在内网机器手动做；这不是配置缺失。
- 三条候选（已向用户摆出）：1 本地手动（选定）/ 2 GitHub self-hosted runner 部署内网（runner 主动外连 github.com，无需入站端口）/ 3 GitHub 主仓 + GitLab pull mirror + 内网 runner。
- 落盘：`publish.yml` 由 `Publish` 改名 **`Release Check`** — tag 只做「构建 + 密钥扫描 + `npm pack --dry-run --ignore-scripts` 文件清单」不发包；公网发布降级为 `workflow_dispatch` + 显式勾选 `publish_public`（默认 false），认证靠步骤内写 `~/.npmrc`（不再用 setup-node `registry-url`，避免与 Nexus 认证写法纠缠）。
- `--ignore-scripts` 是为避免 `prepare`(=husky && build) 二次构建；实测 `npm pack --dry-run --ignore-scripts` 可用、735 文件、不落 tgz。
- 发布指南通道 A-3 改为两步：推 tag（仅校验）→ 内网 `git checkout v0.1.3` + `pnpm install --frozen-lockfile` + `npm publish --registry <hosted>`（prepublishOnly 自动构建）；标注 GitLab 镜像 + 内网 runner 是唯一自动发布例外。A-1 的 GitLab `NPM_AUTH` 项标注「当前不需要」。

## 收尾：删除 .gitlab-ci.yml（用户裁定"删除"）
- 背景：用户问"手动发布还需要用 gitlab 吗"——答**不需要**，手工链路 = GitHub 源码 → 内网电脑 → Nexus，GitLab 只在未采纳的路线 3 里出现。
