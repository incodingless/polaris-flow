## 依赖登记表统一（B 档）

**背景**：`polaris init` 需要安装外部依赖（openspec / codegraph CLI、superpowers 技能包、archify / diagram-design 附带技能），登记信息原本分裂在三处：`assets/sources.ts` 的 `SOURCES`、`integrations/bundled-skills.ts` 的 `BUNDLED_SKILL_SPECS`、`install/channels.ts` 的硬编码 `CHANNEL_COMPONENT_IDS`（漏了附带技能，导致其无法配本地目录）。init.ts 里 5 段手写流程各写一遍"在线→镜像→本地"回退链。

**落地结构**：

- `src/core/deps/registry.ts` —— 唯一声明源。`DEPENDENCIES` 数组，每条含 `method`（判别联合：`npm-cli` / `npx-skills` / `github-copy` / `bundled`）、`probe`（已装判据判别联合）、`fallback`（本地保底载体）、`requiredness`、`trackVersion`、可选 `installer`（覆盖默认分派）
- `src/core/deps/probe.ts` —— 判据执行器（`probeDependency` / `probeInSkillsDir`）
- `src/core/deps/install-dependency.ts` —— 安装分派器（`acquireDependency` / `resolveDependencyVersion`）
- `src/core/assets/sources.ts` **已删除**，`SkillSource` 由 registry 的 `SkillsPlacement` 取代

**重要设计边界（勿推翻）**：

- 声明式只消掉"同类扩展"成本。新增 GitHub 技能目录 / npm CLI 只改 registry 一条 record；全新安装范式（pip / zip / brew）仍需新增 `method.kind` 分支 + installer，这是有意保留的边界
- 本地保底载体三形态（tgz / dir / skills-dir）**不统一**：统一要改离线包格式 + preseed，代价大于收益
- 表用 TS 而非 JSON：`exclude` 是函数谓词，且判别联合能在编译期拦住"增补时漏字段"

**分级（用户裁定）**：required = openspec / superpowers；recommended = codegraph；optional = archify / diagram-design。init 交互提问只覆盖非 optional。

**Polaris 自身不入依赖表（用户裁定，勿再加回）**：它是框架自带技能，随 npm 包分发、由 `core/install.ts` 按平台落盘，没有"获取"这一步。已装判据独立为 `probe.ts` 的 `POLARIS_SELF_PROBE`，`hasSkills(skillsDir,'polaris')` 在 detect.ts 里特判走它（doctor/update/uninstall/prompts 四个调用点行为不变）。`InstallMethod` 因此没有 `bundled` 分支，`autoUpdateDependencyIds()` 与 `trackedDependencyIds()` 合并为后者。

**派生清单**：`CHANNEL_COMPONENT_IDS`（localPathComponentIds）、`UPDATE_DEPENDENCIES`（autoUpdateDependencyIds）、`githubCopyDependencies`、`hasSkills` 的判据全部从表派生，不再有平行数组。

**Breaking**：`polaris init --json` 的 `results[].openspec/superpowers` 改为 `results[].dependencies`。

**package.sh 同步规则**：github-copy 类放 `devops/vendor/bundled-skills/<id>/` 自动打包；npm-cli 类新增时必须加 `pack_cli` 调用。

**测试**：新增 `test/ts/dependency-registry.test.ts`（12 项结构校验）。注意本机沙箱会拦截文件删除（`EPERM unlink/rmdir`），`openspec.test.ts` 的 relocate 用例、`delivery-cleanup.test.ts` 的删除用例会失败，属环境限制非代码问题。

## doctor 改为按登记表逐条检查

原实现只查 openspec 一条（且用 `isCommandAvailable` 只看 PATH，漏掉装到 `~/.polaris/cli/bin` 的情况），superpowers 这个 required 依赖完全没查。

现 `core/doctor.ts` 的 `checkDependencies()` 逐条走 `probeDependency`（与 init 同源），多平台任一命中即已装。分级由 `dependencyDiagnosticStatus(requiredness, present)` 纯函数决定：required 缺失 fail / recommended 缺失 warn / optional 缺失 **skip**。

`DiagnosticStatus` 扩展为 `ok|warn|fail|skip`：skip 的语义是"已知未装但按设计不阻断"，用空心圈 ○，不影响退出码。dashboard `/api/check` 把 skip 归入 ok（面板仅三态）。

注意：`hasDiagnosticFailure` 只认 fail，所以 required 缺失才让 doctor 退出码非零。

## 安装状态记录改名（skills-lock.json → install-state.json）

旧名两处不准：`skills` 覆盖不了同时记录的 commands/agents/rules/hooks 五类资产指纹；`lock` 易被读成包管理那种锁死精确版本的 lockfile（无 integrity、不锁传递依赖）。用户先提议 `plugin-locks.json`，我指出三点问题（`locks` 复数不规范、`plugin` 与 `findPlugin` 的宿主插件语义撞词、polaris 自身资产不是 plugin）后定为 `install-state.json`。

- 文件：`src/core/install/lock.ts` → `install-state.ts`（已删旧文件）
- 类型：`LockFile` → `InstallState`；`LockSourceEntry` → `InstallSourceEntry`（新增 `status: installed|failed|skipped`）
- 函数：`readInstallState` / `saveInstallState` / `writeInstallState` / `getInstallStatePath`
- 删死字段：`lang`、`scope`（以 config.yaml 为唯一真相）、`installedAt`、`updatedAt`
- `sources[]` 纳入附带技能（archify/diagram-design），version 记钉值；新增 `recordedVersion()` in init.ts
- `UpdateResult.lockPath` → `statePath`
- Breaking：不提供旧文件迁移，首次 update 读不到会全量重写一次资产

**语义要点**：`sources[].version` 是「上次安装基线」不是「当前版本」——CLI 是机器级共享的，随时被 `npm i -g` 改，要当前版本只能现查。

### 手动验证记录（临时声明已删除，registry.ts 无残留）

### 本机跑全量测试的坑（与本次改动无关）
`npx vitest run` 在本机并行不可靠：同一批用例单独跑全绿、并行跑出现大量 `Test timed out in 60000ms`（`skills-install.test.ts` 单跑 19 通过但要 236s，每例约 30s）。失败集合每次都不一样。判断改动是否干净时以「单文件串行跑」为准。

### 更正（同日稍晚）：`DependencyOutcome.version` 已删除

上面写的「用户裁定不删」已被推翻——把实测代价（`update-deps` 73ms→5.7s、每次安装多一次 `npm list -g`）摊开后，用户改判删除。

- `DependencyOutcome` 只剩 `{ status, errors? }`；init 的 `{ status: 'skipped', version: 'skipped' }` 同步简化。
- 真正消费版本的是 `resolveDependencyVersion(spec, outcome)`（从安装产物反查）与 update 的 `action.version`（探测到的上游版本），自报字段确实是死重量。
- 删除后 `update-deps` 回到 72ms、542ms/文件，为它加的 60s describe 超时也一并撤掉。
- 教训：判断「字段有没有用」不能只看 grep 到的引用数，要看**填它的代价**；死字段的成本会以 spawn 外部进程的形式漏到测试稳定性上。
