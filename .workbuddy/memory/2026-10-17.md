## 明确「未完成顶层任务数」判断口径（build 派发/分批阈值去歧义）

用户指出 build 的「未完成任务数」阈值有歧义（「3 组」还是「3 个」）。经查 tasks 模板确认 checkbox 打在**两层**（顶层 `N.M` + 子步骤 `N.M.k`），原措辞「未完成任务数」确实含糊。已落盘去歧义（`build/SKILL.md`）：

- Step 2 加**判断口径**块：`未完成顶层任务数` = tasks.md 中**实施任务组**（除最后一组 Documentation Sync 外）里未勾选 `[ ]` 的顶层任务 `N.M` 条数；不计子步骤 `N.M.k`、不计组标题 `## N.`、**不计 DocSync 组**（收尾文档同步，不参与派发/分批决策——否则固定 5 个收尾任务会污染阈值）。
- 2.1 推荐规则「未完成任务数 ≥ 3 / ≤ 2」→「未完成顶层任务数 ≥ 3 / ≤ 2」。
- 2.3 推荐规则「未完成任务数 ≥ 8，或单个 change 顶层任务多」→「未完成顶层任务数 ≥ 8 / < 8」（删掉模糊的「顶层任务多」补充）。
