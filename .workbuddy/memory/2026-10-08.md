## 测试环境踩坑（重要，勿重犯）

**`pkill -f "vitest"` 会杀死自己的 shell**：`-f` 匹配整条命令行，而该命令行本身就含 "vitest"，
于是 pkill 把自己的进程组干掉 → 之后**所有 Bash 调用立即 exit 137（SIGTERM）**，会话 shell 永久失效，
只能靠 Read/Grep/Glob/Write/Edit 继续。**禁止在 Bash 里用 `pkill -f` 匹配自己命令行里出现的字符串**。

**全量 `pnpm test` 在本机不可靠**：本次全量跑出 `24 failed | 447 passed (471)`，跨 7 个文件
（agents-install 3 / cli.test 4 / commands-install 3 / detect-test-command 2 / session-start-sh 3 /
session-start 1 / skills-install 7）。判定为**环境/负载导致，非本次改动引起**，依据三条：

1. **同代码三次全量跑的失败数不一致**（22 → 24 → 27）——非确定性即非断言性问题
2. **`cli.test.ts` 4 个 smoke 用例耗时 160s**（单条 37~43s），正常应 <1s → 机器被打满
3. **`commands-install.test.ts` 单跑 6/6 全绿**（含本次全部改动）；`manifest.test.ts` 5/5 全绿
   （证明 `readAssets('zh')` 读带 `prototype/` 子目录的 commands 完全正常）

**结论**：验证命令改动时**单跑 `npx vitest run test/ts/commands-install.test.ts`**，不要用全量结果判真伪。
全量失败里 `skills-install` 的 `validateSkillAssetsNoCrossSkillParentRefs` 一组属**存量技能资产债**
（与 commands 无关）；`session-start` 超时为已知存量债。

**另注**：`assets/zh/skills/prototype/build/evals/` 与 `example/` 下有残留临时产物
