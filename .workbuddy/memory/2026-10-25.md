# 2026-10-25 工作日志

## 诊断「polaris update 更新不到 0.6.0」根因

用户发布 0.6.0 后，测试机执行 `polaris update` 仍是 0.5.0。结论：**发布正确，问题在测试机的旧程序 + update 的 registry 来源未解决**。

铁证（从 Nexus tarball 逐一拉取 `dist/core/deps/version.js` + `npm.js` 对比）：
- **0.5.0**：`PACKAGE_NAME='@polaris/polaris-flow'`（错包名）+ `getLatestNpmVersion` 硬编码 `https://registry.npmjs.org/<pkg>/latest`（走公网）。双重 bug → 查公网 `@polaris/polaris-flow` → 404 → `unreachable` → 永远不更新。
- **0.5.1**：`PACKAGE_NAME='polaris-flow'`（已修）+ `npm view`（走用户默认 registry，**不带 --registry**）。
- **0.6.0**：同 0.5.1。

两层死锁：
1. **直接死锁**：测试机装的 0.5.0 旧程序，update 逻辑坏了查不到新版本；修复在 0.5.1+ 里但旧程序升不上去。
2. **升到 0.6.0 后仍会踩**：`self-update.ts` 的 `npm install -g polaris-flow@latest` 与 `npm.ts` 的 `npm view polaris-flow version` 都**不带 `--registry`**，走测试机 npm 全局默认 registry。而 `install.sh` 安装时只用临时 `--registry` 参数、**不写 ~/.npmrc**，故测试机默认 registry=公网 npm → 公网无 polaris-flow（404）→ 0.6.0 的 update 依然 `unreachable`。

源码里 grep 无任何 Nexus/registry 常量，update 完全依赖机器全局 npm registry 配置。

修复方向（待用户裁定）：
- 动作1（解锁测试机）：`npm install -g polaris-flow@latest --registry http://192.168.103.96:8081/repository/npm-group/`
- 动作2（让 update 自愈）：给 `npm view`/`npm install -g` 显式带 registry，来源建议 `环境变量 + 默认 Nexus group`（与 install.sh 的 `NPM_REGISTRY` 对齐），或读 ~/.npmrc（但 install.sh 不写、不可靠）。

## 实现方案 B：update 显式带 registry（2026-10-25）

用户裁定方案 B（环境变量 + 默认 Nexus）。落点：
- `polaris-constants.ts` 新增 `DEFAULT_NPM_REGISTRY`（`http://192.168.103.96:8081/repository/npm-group/`，与 install.sh DEFAULT_REGISTRY 对齐）+ `POLARIS_NPM_REGISTRY_ENV='POLARIS_NPM_REGISTRY'`（唯一源）。
- `npm.ts` 新增 `resolveNpmRegistry()`（环境变量 > 默认 Nexus）；`getLatestNpmVersion` 的 `npm view` 显式加 `--registry`。
- `self-update.ts` 的 `buildGlobalInstallInvocation` 四种包管理器（npm/pnpm/yarn/bun）均加 `--registry`。
- `channels.ts` 的 `CHANNEL_ENV_KEYS.npmRegistry` 从硬编码字符串改为引用 `POLARIS_NPM_REGISTRY_ENV`（唯一源收敛）。

关键判断：deps 层（openspec/codegraph）已有 registry 解析（channels 三层：CLI flag > env > polaris.yaml），且它们是公网包、默认机器 registry 也能装；唯一坏的是程序本体 polaris-flow（纯私有包，公网 404），故只给它加「默认 Nexus」语义，不动 channels 的「默认机器 ~/.npmrc」语义（两套语义刻意不同）。

验证：tsc/eslint 全绿；build 后 dist 确认带 `--registry`；实测 `resolveNpmRegistry()` 返回默认 Nexus、`getLatestNpmVersion('polaris-flow')` → 0.6.0、`@fission-ai/openspec` → 1.15.0（经 Nexus proxy 转发）。版本 0.6.0 → **0.6.1**（patch），CHANGELOG 加 0.6.1 Fixed。

⚠️ 仍未发布：Nexus 最新仍是 0.6.0，需 `devops/publish.sh` 发 0.6.1 后，测试机手动 `npm install -g polaris-flow@latest --registry <Nexus group>` 解锁一次（旧版 0.5.0 的 update 是坏的，无法自愈，必须手动升到 0.6.1 之后 update 才正常）。

## install.sh 持久化 registry 到 ~/.npmrc（2026-10-25）

用户裁定「更新与维护都在 root 下操作」，故不区分 sudo/SUDO_USER，直接写 `$HOME/.npmrc`。新增 `ensure_npmrc_registry()`（install.sh）：
- 无 ~/.npmrc → 生成 `registry=<REGISTRY>`
- 有且 registry 值匹配（去末尾斜杠规范化比较）→ 不动
- 有但无 registry 键 → 追加（保留其它内容如 _auth）
- 有且不匹配 → 打印 warn 提示 + `sed -E "s#...#...#"` 覆盖 registry 行（tmp+mv，避免 sed -i 跨平台差异）

调用点：安装成功后（`"$BIN" --version` 之后、Next steps 之前）。dry-run 不涉及（在安装前即 exit）。

关键：`install.sh` 不在 npm 包 `files` 列表（files=dist/bin/assets/scripts/postinstall.js），故本次**不 bump 版本**，改动经重新分发 install.sh / 重打离线包（package.sh）生效。四场景冒烟测试全过（无文件生成/匹配保持/不匹配覆盖/无键追加保留 _auth）。

## install.ps1 同步持久化 registry（2026-10-25）

与 install.sh 的 ensure_npmrc_registry 对称，给 install.ps1 加 `Ensure-NpmrcRegistry` 函数（第 169 行）+ 安装验证后调用（第 309 行）。逻辑一致：无 %USERPROFILE%\.npmrc → 生成；有且匹配（TrimEnd('/') 规范化）→ 不动；有但无 registry 键 → 追加；不匹配 → Write-Warn 提示 + [regex]::Replace 覆盖。

⚠️ 改 install.ps1 的**强制方式**：必须用 Python 字节级 patch（读 bytes → 断言 BOM efbbbf → 文本 CRLF 替换 → 写回 BOM+utf-8），**不能用 Edit 工具**（可能破坏 BOM/CRLF）。改后验证：`xxd` 查 BOM、`grep -c $'\r'` 应等于总行数（332 全 CRLF、无孤立 LF）、`file` 显示 "UTF-8 (with BOM) ... with CRLF"。本机无 pwsh，无法做 PowerShell 语法/运行验证，需 Windows 实测。
