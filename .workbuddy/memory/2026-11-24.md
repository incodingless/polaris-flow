## polaris doctor 输出语言跟随 init 选择（feature/update-command-improve 分支）

- 用户报障：init 选了中文，`polaris doctor` 输出仍是英文。
- 根因：`core/doctor.ts` 诊断文案硬编码（部分中英混杂），`commands/doctor.ts` 不读 `.polaris/config.yaml` 的 `language`。
- 方案取舍：core 依层不可 import `commands/i18n` 的 `t()`，dashboard 也不 import commands → 弃 messages.yaml 路线；采用 `runDiagnostics(projectPath, scope, lang: Languages = 'zh')`，doctor 双语文案表随判定逻辑放 `core/doctor.ts` 内（`MESSAGES` const + `{name}` 占位符插值）。
- 改动文件：`src/core/doctor.ts`（文案表 + lang 贯穿 5 个 check 函数）、`src/commands/doctor.ts`（loadPolarisConfig 取 language）、`src/dashboard/api/check.ts`（resolveScope → resolveCheckContext，一并传 lang）、`test/ts/doctor.test.ts`（新增 zh/en 文案断言）、`CHANGELOG.md`（追加到已有 0.9.3 条目，main=0.9.1）。
- 语言取值约定与 `polaris update` 对齐：config 缺失落 zh；`--json` 的 message 一并本地化。
- 验证：build ✓、全量 66 文件 634 测试 ✓、format/lint ✓；用 bwda 项目（language: "zh"）实测 doctor 输出全中文。
- 踩坑：`extractSemver` 返回 `string | null`，插值参数类型 `string | number` 拒收 null → `{ actual: actual ?? 'unknown' }`（verdict='drifted' 已保证 concrete）。

## 全部用户面命令输出语言跟随 config（同日第二轮）

- 用户要求：除 `polaris init` 外所有命令都读 `.polaris/config.yaml` 的 `language` 决定交互输出语言。
- scope 裁定：只动用户面命令（status / uninstall / dashboard / doctor 收口）；runtime 命令（state / worktree / task-state-entry 等）输出是 hook 与技能消费的结构化数据，不本地化；`update` 已合规不动（避免越权重构）。
- 现状修正：`uninstall.ts` 原本**全中文硬编码**（英文用户受害）、`status.ts` 全英文硬编码、dashboard 中英混杂。
- 落地：`commands/i18n` 新增共享解析器 `resolveProjectLanguage(projectPath)`（config > zh）与插值助手 `tf()`（`t()` 无参数版，此前 messages.yaml 的 `{version}` 是死键）；messages.yaml 补 40 余条 status/uninstall/dashboard 键；`startDashboard` 增加 `lang` 选项（dashboard/server.ts import commands/i18n——dashboard → commands 的新边，如被质疑可下沉 i18n）。
- `--json` 输出不本地化（机器可读）；status 的 `error` 字段维持 `not a git repository` 稳定值。
- 验证：build/lint/format ✓；i18n/doctor/cli/dashboard 相关单测 ✓；临时目录造 zh/en config 实测 status + uninstall 输出正确；bwda 项目 doctor 中文 ✓。
- ⚠️ 环境性坑：全量 vitest 中 agents-install / commands-install / cli 等 spawn 型测试 60s 超时——这批测试真连 npm registry / GitHub 探测版本，网络卡死即挂；**stash 本轮改动后同样失败（8 个 vs 5 个）**，判定与本轮无关。提交前需在网络正常时重跑全量确认。

## polaris update 范围词表重构（同日第三轮，Breaking）

- 用户裁定（AskUserQuestion 两问敲定）：① `--only`/`--skip` 可选值只留 6 项，删除 skills/commands/agents/rules/hooks 资产细分与单独的 program/assets；② 第 1 项「program+assets」合成一个组名 → 定名 `polaris`。
- 新语义：`polaris`（程序本体+资产五类）= **默认范围**（默认不再自动更依赖）；`deps` = 三方依赖组；`all` = polaris+deps；openspec/superpowers/codegraph 单依赖照旧。
- 权威源 `core/update/scope.ts`：`UPDATE_TARGETS = ['polaris','deps','all',...trackedDeps]`；内部 `UpdatePlan` 结构（program bool + assets + deps）未动，update.ts 编排零改动。

- 追加改名（用户裁定）：组名 `polaris` → `framework`（避免与产品名/插件目录名 `skills/polaris` 混淆）。词表终版：`framework | deps | all | openspec | superpowers | codegraph`。注意 `skills/polaris` 是插件目录名（POLARIS_PLUGIN_NAME），与本 token 无关，勿顺手改。
