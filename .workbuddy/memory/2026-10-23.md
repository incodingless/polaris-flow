## 「普通用户装不了 / sudo init 导致文件 root 归属」彻底修复

用户现场：Linux，`npm prefix -g = /usr`（不可写），**且没装 git**。普通用户 `polaris init` 后 OpenSpec / Codegraph 报 EACCES → 用户改用 `sudo polaris init` → 项目里 `.polaris/`、`.trae-cn/` 全 root 归属，之后普通用户改不了文档。

### 根因（两层）
1. `ensureOpenSpecCli` / `ensureCodegraphCli` 在全局 prefix 不可写时**直接 return failed** 并引导 `sudo npm install -g` → 用户理解成 `sudo polaris init`。
2. `init` 完全没有 root 检测，谁 sudo 都畅通无阻。

### 修复（架构级：新增用户级 CLI 安装通道）
- `polaris-paths.ts`：`getUserCliPrefixDir()` = `~/.polaris/cli`、`getUserCliBinDir()` = `~/.polaris/cli/bin`。
- `deps/npm.ts`：
  - `resolveCliInstallTarget()` → `{kind:'global'}`（全局可写）或 `{kind:'user', prefix: ~/.polaris/cli}`（不可写）。**取代** 原 `printNpmPrefixNotWritableHint`（已删）。
  - `resolveCliExecutable(name)` → 按 **PATH → `~/.polaris/cli/bin` → pnpm 全局 bin** 解析，返回绝对路径；取代 openspec.ts 的 `isCommandAvailable` 内部实现与 codegraph.ts 的 `resolvePnpmGlobalCommand`（已删）。pnpm bin 目录 `Map` 缓存。
  - `isUserLevelCliExecutable()` / `formatUserCliPathHint()`。
- `install/cli-installer.ts`：`buildNpmGlobalInstallArgs` / `npmInstallGlobal` / `installCliFromGitRepo` / `installCliFromLocalDir` 全部加 `prefix?` 参数（当前置参数顺序：`npmInstallGlobal(target, registry, timeoutMs, prefix)`）。
- `openspec.ts`：`buildOpenSpecInitInvocation` 的 command 改为 `resolveCliExecutable('openspec') ?? 'openspec'` —— **用户级安装不在 PATH 上也能跑**，这是整条链路的关键一步。
- `codegraph.ts`：`resolveCodegraphCommand` = `resolveCliExecutable('codegraph')`。
- `init.ts`：`evaluateRootGuard(uid, allowRoot)` 纯函数 + `assertNotRunningAsRoot()`（`uid===0` 且 `POLARIS_ALLOW_ROOT!=1` → 打印 `rootNotAllowed` 后 `exit 1`）；`warnIfGitMissing()`；`warnIfCompanionCliInUserDir()`。
- `i18n/messages.yaml` 新增 3 key：`rootNotAllowed`（多行块标量，含正确顺序 + chown 补救 + 逃生舱）、`gitMissing`、`companionCliInUserDir`。
- `install.sh`：结尾预装建议改为「openspec + codegraph 缺哪个列哪个」，并声明「sudo 只用于装 CLI，初始化项目必须普通用户」；全局不可写拒绝分支删掉已不成立的「init 会继续报 EACCES」，只留 PATH + `update` 两条理由。

- **不再引导 sudo 装伴生 CLI**。`polaris-flow` 本体仍要求全局安装（`polaris update` 升级自身要写全局 + PATH），但 `init` 需要的 openspec / codegraph 一律走用户级通道。

## Windows 「git 有、bash 无」诊断修复（用户现场截图）

用户 Windows 机器 `polaris doctor` 显示 `✗ bash: not found in PATH` 但 `✓ git: available`。

### 根因（最常见的一种，值得记住）
**Git for Windows 默认安装（"Git from the command line and also from 3rd-party software"）只把 `cmd\` 加进 PATH** —— 那里有 `git.exe`；而 `bash.exe` 在 `bin\` 下，默认不进 PATH。于是出现「git 可用、bash 找不到」这种最迷惑的组合。用户装了 Git 也没用。

### 裁定重申：bash 是硬依赖，不做 PowerShell 替代
