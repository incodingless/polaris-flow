## 核清 `tweak` 的编排关系（用户问答，只读未改）
- **tweak 不是纯编排技能**：它是 tweak 档的**单入口执行体**（入口 + 执行二合一）。编排只占三处：
  Step 0 进入任务 / Step 3 升档闸门 / Step 7 推进 ship。
- **它的顶层 `phase` 写入点只有三处**：`specify`（建任务，`task-entry` → initPatches）、
  `plan`（§4.1 worktree 决策，两处分支各一次）、`ship`（§7 出口）。**不写** design/tasks/build/verify。
- **对外技能引用（polaris）**：`coding:ship`（唯一常规下游，Step 7 后 `state next` → ship）、
  `coding:normal`（升档转交，`upgrade-check.md` §3.1）、`coding:specify`（拆分预检 §5 批量拆分，每项走 specify 建独立 change）、
  `polaris:subagent-probe`（H10 条件；仅用户显式要求派发时）。
  非 polaris：`opsx:new` / `opsx:apply` / `opsx:archive`、`superpowers:requesting-code-review`（§5.5）；**禁用** superpowers 两个派发驱动器（H13）。
- 🔴 **新发现（记入 MEMORY）**：阶段表的 `channelSkill` **只登记 specify / plan 两个阶段**，
  → 通道技能**必须**只把顶层 `phase` 写成 `specify→plan→ship`。一旦写了 `tasks`/`build`/`verify`，
  `skillForModePhase` 无覆盖会返回同名**节点技能**（把 tweak 任务交给 `tasks`/`build`/`verify`）。
  现状靠「技能从不写那些阶段」维持，**代码里没有护栏** —— 属隐式约定，改动前必读。
