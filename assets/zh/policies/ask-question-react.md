# 用户询问应答交互规则

> 通用询问机制。各skill 共同遵守的全局约束。

任何 SKILL 在「向用户发问」步骤均可引用本文件；本文件**不绑定**具体业务问题内容，也**不绑定**具体工具名——工具名按下方「平台询问工具注册表」查表确定。

## 适用范围

- 任何需要向用户征询决策、确认、偏好的场景
- 一个决策点内需要拆多个子问题串行询问的场景- 多决策点串行的场景

## 平台询问工具注册表

调用方从 `.polaris/config.yaml` 的 `platform` 字段读平台 id，按下表查工具名与能力。

| platform | 询问工具名 | 单次调用支持多 question | 单 question 选项数上限 | 备注 |
|---|---|---|---|---|
| `trae` / `trae-cn` / `claude` / `cursor` / `codebuddy` | `AskUserQuestion` | 支持（`questions` 数组，工具内部串行显示） | **5**（有效 4 +「其他」1） | 见下方「选项数硬上限」 |
| `qoder`       | （无原生结构化询问工具） | — | — | 直接走文本降级模式 |
| （未登记）      | — | — | — | 直接走文本降级模式 |

### 选项数硬上限（各平台一致）

各平台结构化询问工具**最多 5 个选项槽位**：

| 槽位 | 数量 | 含义 |
|---|---|---|
| **有效选项** | ≤ **4** | 业务可选项（A/B/C/D），互斥、可执行 |
| **其他** | **1** | 固定追加「其他 / 以上都不合适」类出口，供用户跳出预设 |
| **合计** | ≤ **5** | 有效选项数 +「其他」= 总选项数，不得超过 5 |

因此：

- 设计问题时应保证**有效选项 ≤ 4**，再额外加 1 个「其他」
- **有效选项 > 4**，或**总选项数（含「其他」）> 5** → **不得**调用询问工具，**直接走文本降级模式**（与工具调用失败同属降级触发条件）
- 「其他」不可占用有效选项名额去塞第 5 个业务选项；第 5 槽专留给「其他」

## 能力差异处理

| 平台能力 | 调用方动作 |
|---|---|
| 支持「单次多 question」 | 同一决策点的全部子问题在**单次**询问工具调用中传入 `questions` 数组 |
| 不支持「单次多 question」 | 同一决策点的子问题**拆多次调用**，每次传一个 question，串行等答完再发下一个 |
| 无询问工具 | 直接走文本降级模式 |
| 单 question 有效选项 > 4（或总选项 > 5） | 直接走文本降级模式（不调用询问工具） |

> 调用方若不确定某平台是否支持「单次多 question」，按「不支持」分支处理（拆多次调用）。

## 核心原则

1. **决策点内合并、决策点间串行**：同一决策点的多个子问题在单次询问工具调用中传入全部 questions（若平台支持单次多 question，工具内部串行显示）；多个决策点串行多次调用，每次传当前决策点的全部子问题
2. **不绑定具体问题**：本文件只规定「如何问」，不规定「问什么」——问题内容、拆问粒度由调用方 SKILL 自定
3. **不绑定具体工具名**：工具名按「平台询问工具注册表」查表确定；调用方不假设固定工具名
4. **失败 / 超限降级**：若无法使用注册表查得的询问工具，或单 question **有效选项 > 4 / 总选项 > 5**，判定本次须走文本降级；工具失败时本会话后续决策点仍可再试工具，但超限 question 一律文本呈现

## 拆问原则（调用方 SKILL 自定具体拆法）

调用方 SKILL 负责把一个决策点拆成多个子问题，拆法由 SKILL 自定。本文件只约束：

| 原则 | 要求 |
|---|---|
| 决策点内合并（平台支持单次多 question 时） | 同一决策点的所有子问题在**单次**询问工具调用中传入 `questions` 数组；工具内部串行显示，用户逐个回答 |
| 决策点内拆多次（平台不支持单次多 question 时） | 同一决策点的子问题**拆多次调用**，每次传一个 question，串行等答完再发下一个 |
| 决策点间串行 | 多个决策点**串行多次**调用询问工具；决策点 N 全部问题答完后才发起决策点 N+1 的调用 |
| 条件分支 | 若决策点 N 的答案使决策点 N+1 无意义 → 跳过 N+1，直接进 N+2 或结束 |
| 等待阻塞 | 每次调用询问工具后必须停止流程，等用户回复；不得自答自续、不得预填状态字段 |

## 单次询问呈现要求

无论询问工具还是文本降级，每次询问必须包含：

1. **正在问什么**：当前子问题在决策点中的位置（如「子问题 2/4：评审范围」）
2. **清晰可选项**：互斥、可执行
3. **影响说明**：每个选项的后果一句话
4. **等待阻塞**：问完即停，不得自答自续、不得预填状态字段

## 工具调用规范

### 优先注册表查得的询问工具

每次询问优先调用「平台询问工具注册表」查得的工具：

- 按平台能力决定单次传全部 questions（支持多 question）还是拆多次调用（不支持）
- 单次调用传入当前决策点的全部子问题（`questions` 数组含 1–4 个 question，由 SKILL 按拆问结果决定）
- **每个 question：有效选项 2–4 个 + 固定 1 个「其他」＝合计 ≤ 5**；超出则本 question **不调工具、直接文本降级**
- 每个选项携带简短 label（≤12 字符）+ 影响说明；「其他」的影响说明写清「自由补充 / 跳出预设」
- 推荐项放第一位、label 末尾加「（推荐）」；推荐仅作说明，不自动选择
- 等待用户逐个回复，不并行输出文本选项

### 失败 / 超限降级

出现以下任一情况时，当前决策点（或当前超限的子问题）走文本降级：

1. 询问工具调用失败
2. **有效选项 > 4，或总选项数（含「其他」）> 5**——不调用工具，直接文本降级

降级后：

1. 在对话中逐个输出编号选项（A/B/C/…）；文本模式**不受**「5 槽」限制，可按需列出全部业务选项（建议仍 ≤ 10 项，编号到 J）+ 每项影响 + 要求用户回复编号
2. 停止流程，等用户逐个回复
3. **下一个决策点再次尝试询问工具**——不记忆「本会话不可用」结论；但每个 question 仍须先过「≤4 有效 + 1 其他」校验，超限的继续文本降级

> 与 [decision-point.md](./decision-point.md) 的差异：decision-point.md 失败一次后本会话永久降级；本文件每次都重试。调用方按场景选用。

#### 文本降级模式格式

每个子问题按以下格式逐个输出：

```text
[子问题 i/N] <当前子问题在问什么>

A. <选项 1> — <影响>
B. <选项 2> — <影响>
C. <选项 3> — <影响>
D. <选项 4> — <影响>
…（文本模式可超过 4 项；建议最多 10 项，编号延续到 J）

请回复编号。
```

## 调用方 SKILL 职责

引用本文件的 SKILL 需自行负责：

1. **定义决策点**：在哪个步骤触发询问
2. **定义子问题序列**：拆成哪几个子问题、每个问什么、条件分支如何跳过
3. **定义问题内容**：选项 label、影响说明、推荐项
4. **定义问题形式**：单选/多选/问答；非选择模式则在对话中提出明确的问题并等待用户回复
4. **查注册表确定工具**：从 `.polaris/config.yaml` 读 `platform` → 查本文件注册表 → 确定工具名与能力
5. **执行询问**：按本文件的「决策点内合并、决策点间串行」原则调用查得的询问工具或文本降级
6. **消化答案**：每收到一个子问题答案，更新对应状态字段或进入下一决策点

## 不做的事

- **不定义具体问题**：本文件不知道「是否启动 OV」「TDD 策略选哪个」——那是调用方 SKILL 的事
- **不替代 decision-point.md**：两文件并列，调用方按场景选用；本文件侧重「决策点内合并 + 决策点间串行」机制，decision-point.md 侧重「通用阻塞点 + 失败永久降级」机制
- **不缓存工具失败**：每次都重试询问工具
- **不硬编码工具名**：工具名一律经注册表查得，调用方不得在 SKILL 内写死 `AskUserQuestion`
