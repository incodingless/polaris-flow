# 代码审查报告模板

生成审查报告时，按以下结构输出（输出时去掉代码块标记，直接输出标题与正文）。语言与用户输入保持一致。

```
# 代码审查报告

## 审查概览
- 审查目标：【文件/目录/仓库路径】
- 审查范围：【全量 / 仅 diff】
- 技术栈：【识别的语言与框架】
- 审查覆盖：【通用五维度 + 本次加载的专项清单（Java/Spring 栈时为接口/质量/并发/事务/性能/安全）】
- 总体评分：X / 10
- 合并建议：✅ 可合并 / ⚠️ 修改后可合并 / ❌ 不建议合并

## 风险摘要
【一段话说明最需要优先处理的风险，及其可能造成的后果】

## 关键问题（Critical / Major）

### [C-1] 【问题标题】 — 🔴 Critical
- 位置：`文件:行`
- 问题：【现象 + 触发条件 + 潜在后果】
- 修复建议：【具体改法，附代码示例】

### [M-1] 【问题标题】 — 🟠 Major
- 位置：`文件:行`
- 问题：【……】
- 修复建议：【……】

## 一般问题（Minor）

### [m-1] 【问题标题】 — 🟡 Minor
- 位置：`文件:行`
- 问题：【……】
- 修复建议：【……】

## 优化建议（Nit，可选）

- 【命名/注释/风格等非功能性建议，可合并列出】

## 架构评估（可选，当审查范围含多文件/模块时）

- 模块边界：【……】
- 依赖方向：【……】
- 主要风险：【……】
```

## 报告注意事项

- Critical 与 Major 必须逐条列出，每条含位置、问题、修复建议三要素；
- Minor 可逐条列出；Nit 可合并为列表从简；
- 只输出有问题的审查项：未发现问题的维度/清单不单独列出，由「审查概览」的「审查覆盖」说明本次实际检查范围；
- 修复建议中的代码示例要可直接使用，避免伪代码。
