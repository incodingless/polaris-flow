# 审查维度与严重级别定义

## 五个审查维度

### 1. 正确性（Correctness）
关注代码是否按预期工作。

检查点：
- 逻辑错误：条件判断、循环边界、空值/undefined 处理
- 边界条件：空输入、空数组、零值、极端值、越界
- 错误处理：异常是否被吞掉、错误码是否正确传递
- 并发与竞态：共享状态、锁、异步时序、脏读
- 返回值与副作用：函数是否有预期外的副作用

### 2. 安全性（Security）
对照 `security-checklist.md` 逐项检查，重点关注：
- 注入类（SQL / 命令 / 模板注入）
- 敏感信息泄露（硬编码密钥、日志打印凭据）
- 认证与授权缺陷（缺失鉴权、越权、弱会话）
- 加密误用（弱哈希、自研加密、硬编码 IV）
- 依赖漏洞与反序列化风险

### 3. 性能（Performance）
- 算法复杂度：O(n²) 及以上、不必要的重复计算
- 数据库：N+1 查询、缺失索引、全表扫描
- IO 与阻塞：同步阻塞调用、频繁文件/网络读写
- 内存：内存泄漏、大对象未释放、无界缓存

### 4. 可维护性（Maintainability）
对照 `code-smells.md` 识别代码异味：
- 命名、重复代码、超长函数、过深嵌套
- 魔法数字、死代码、过度耦合
- 可测试性：是否难以编写单元测试

### 5. 架构（Architecture）
- 模块边界与职责单一性
- 依赖方向与循环依赖
- 分层是否清晰、跨层调用
- 可扩展性与可替换性

## 专项清单（技术栈深度检查）

当识别到 Java/Spring（Spring Boot / Spring Cloud / MyBatis）技术栈时，深度审查需额外对照 `references/java-*.md` 专项清单，作为通用五维度在以下领域的深度补充：

- `java-api-design.md` — 接口设计（参数校验/敏感数据/接口拆分/返回格式）
- `java-code-quality.md` — 代码质量与可维护性（分层/异常/日志/类设计）
- `java-concurrency.md` — 并发与线程安全（线程池/竞态/工具类/死锁）
- `java-database.md` — 数据库与事务（SQL/连接池/事务边界/分布式一致性）
- `java-performance.md` — 性能（循环远程调用/N+1/分页/内存泄漏/缓存）
- `java-security.md` — 安全编码（注入/访问控制/加密/文件路径/SSRF）

专项清单中的严重度已按下方四级定义统一标注，与通用维度共用同一套级别，报告不再出现「高/中/低」。

## 严重级别定义

| 级别 | 含义 | 处理要求 |
|------|------|----------|
| 🔴 Critical | 安全漏洞、数据丢失/损坏、可导致生产事故、资金损失 | 必须修复后才能合并/上线 |
| 🟠 Major | 明显 bug、严重性能问题、违反核心架构原则 | 应在本次迭代内修复 |
| 🟡 Minor | 代码异味、可维护性问题、轻微性能问题、边界处理不足 | 建议修复，可排期 |
| 🔵 Nit | 命名、注释、格式、风格等非功能性建议 | 可选，不强制 |

---

## 评分与结论

审查结束给出：
1. **总体评分**（1-10 分），依据：Critical/Major 的数量与严重程度加权；
2. **合并建议**：✅ 可合并 / ⚠️ 修改后可合并 / ❌ 不建议合并；
3. **风险摘要**：一段话说明最需要优先处理的风险。

## 分级原则

- 不确定严重程度时，**宁可降一级**（避免误报恐慌），但安全类问题不适用此规则（安全从严）；
- 同类问题重复出现时，归并为一条，注明「共 N 处」；
- 没有依据的问题一律不报。
