# 代码异味目录（Code Smells）

代码异味是可维护性问题的信号，不一定是 bug，但会增加后续修改成本与出错概率。审查时对照本目录识别，并给出重构建议。

## 结构类异味

| 异味 | 特征 | 重构建议 |
|------|------|----------|
| 超长函数（Long Method） | 函数超过约 50 行，做多件事 | 拆分为多个职责单一的小函数 |
| 超大文件/类（Large Class） | 单文件超过约 500 行 | 按职责拆分为模块/多个类 |
| 上帝对象（God Object） | 一个类/模块承担过多职责 | 按单一职责原则拆分 |
| 数据泥团（Data Clumps） | 多个数据总是一起出现 | 提取为对象或结构体 |
| 重复代码（Duplicated Code） | 相同逻辑在多处出现 | 提取公共函数/基类 |

## 复杂度类异味

| 异味 | 特征 | 重构建议 |
|------|------|----------|
| 过深嵌套（Deep Nesting） | 条件/循环嵌套超过 4 层 | 提前返回（early return）、卫语句、提取函数 |
| 长参数列表（Long Parameter List） | 函数参数超过约 5 个 | 封装为参数对象 |
| 魔法数字（Magic Numbers） | 出现无命名含义的数字字面量 | 提取为具名常量 |
| 复杂条件（Complex Conditional） | 多重 && / \|\| 且难以理解 | 提取为具名布尔方法 |
| 圈复杂度过高（High Cyclomatic Complexity） | 函数圈复杂度超过 10 | 拆分条件分支、提取子函数、查表法 |

## 语义类异味

| 异味 | 特征 | 重构建议 |
|------|------|----------|
| 特性依恋（Feature Envy） | 函数过度使用其他对象的数据 | 把逻辑移到数据所属的类 |
| 散弹式修改（Shotgun Surgery） | 改一个需求要动多处文件 | 集中相关逻辑 |
| 死代码（Dead Code） | 永不执行的代码、未引用的函数/变量 | 删除 |
| 过度注释（Over-commenting） | 注释解释「做了什么」而非「为什么」 | 用命名替代，保留「为什么」注释 |

## 设计类异味

| 异味 | 特征 | 重构建议 |
|------|------|----------|
| 循环依赖（Circular Dependency） | 模块 A 依赖 B，B 又依赖 A | 提取公共接口，打破环 |
| 依恋链（Message Chains） | `a.getB().getC().getD()` | 隐藏委托、遵守迪米特法则 |
| 平行继承体系（Parallel Inheritance） | 每加一个类都要同步改另一个体系 | 合并或解耦 |

---

## 记录格式

```
[异味名] 位置（文件:行/函数） - 简述 - 建议
```

示例：
```
[超长函数] src/order.js:120 processOrder() - 函数 200 行，含下单、支付、通知三件事 - 拆分为 createOrder/pay/notify
```
