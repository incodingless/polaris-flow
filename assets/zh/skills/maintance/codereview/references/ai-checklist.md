# AI 审查清单（日常精读唯一加载）

> **定位**：本文件是 AI 日常精读唯一加载的清单，只含 AI 主导条目（规则做不了的语义判断）与重叠条目的语义面。**规则层条目不在此文件**——由 `analyze.py` / Sonar 检出，AI 只引用结论。
>
> **加载条件**：每次深度审查（Step 4）必载。原 6 份清单（security-checklist / java-database / java-code-quality / java-concurrency / java-api-design / java-performance）属**规则对照组**，仅在三种时机打开：① Sonar 经用户确认跳过后的 AI 兜底核查；② 规则误报申诉核对；③ 重叠项佐证核对。
>
> **归属统计**：90 项 = 规则层 49（Sonar/脚本，本文件不含）+ 重叠 24 + AI 主导 17。编号单源在各原清单。
>
> **置信度映射**（与 rubric §评分与结论一致）：清单静态边界「可审=高」「部分可审=中」「不可审=不报」；中置信发现不计入评分与合并建议，进报告「待人工确认」。

## security-checklist（AI 主导 4 + 重叠语义面 6+1）

### AI 主导

| 编号 | 审什么 | 判定要点 | 静态边界 |
|---|---|---|---|
| SEC-10 | 跨信任边界输入无校验 | 输入从外部（请求 / 消息 / 第三方响应）进入受信区时是否校验；白名单优先于黑名单 | 可审=高（边界可定位） |
| SEC-12 | 水平 / 垂直越权 | 是否仅信前端传参或参数 role 判权；服务端是否复验身份与角色 | 部分可审=中（需业务流佐证） |
| SEC-13 | IDOR：资源 ID 来自请求且无归属校验 | 直接用请求 ID 查库、未校验资源归属（属主 / 租户 / 组织）即返回或变更 | 部分可审=中（归属规则需业务确认） |
| SEC-18 | 下载未鉴权、路径用户可控 | 下载接口是否校验登录态 + 归属 + 路径白名单 | 部分可审=中 |

### 重叠（规则检出即定论，AI 只补语义面）

| 编号 | 语义面（AI 审这个） | 规则面（引用 Sonar/脚本） |
|---|---|---|
| SEC-06 XSS | 输出是否进入危险渲染上下文（富文本、模板、属性） | 未编码输出模式可扫 |
| SEC-11 接口未鉴权 | 白名单范围是否与业务公开面一致（过宽 / 过窄） | `permitAll("/**")` 等配置可扫 |
| SEC-14 CSRF | 关闭防护是否与认证方式匹配（JWT 无状态可关，Cookie Session 不可） | `csrf().disable()` 可扫 |
| SEC-17 上传 | 校验策略是否与存储位置匹配（可执行目录、CDN 回源） | 类型/大小校验缺失可扫 |
| SEC-29 异常栈返回 | 返回给前端的文案是否区分用户态（displayMessage vs message） | 异常栈直返模式可扫 |
| SEC-31 SSRF | URL 白名单是否覆盖重定向后的目标；内网段判断是否完整 | URL 来源用户可控模式可扫 |
| SEC-F01 @PreAuthorize 缺失 | URL 层规则是否足以覆盖方法级写操作（内部调用、多入口） | 注解缺失可扫 |

## java-database（AI 主导 6 + 重叠语义面 3）

### AI 主导

| 编号 | 审什么 | 判定要点 | 静态边界 |
|---|---|---|---|
| DB-03 | 条件下推 | 可被存储引擎过滤的条件是否在应用层内存过滤（先查全量再 filter） | 可审=高 |
| DB-07 | DB 函数权衡 | 计算 / 转换放 DB 还是应用层：看聚合吞吐、索引失效、可测试性，不是一律禁 DB 函数 | 可审=高 |
| DB-08 | 物理删除 vs 业务要求的逻辑删除 | 是否符合业务约定的留存 / 审计要求（纯业务约定，团队红线清单典型条目） | 部分可审=中（需业务约定） |
| DB-10 | 事务原子性（该不该包） | 多写操作业务上是否要求原子——规则判不了「该不该」，只判「有没有」 | 可审=高（语义判断） |
| DB-18 | 跨服务多写一致性 | 一致性方案（Saga / TCC / 本地消息表 / Outbox）是否与实际风险匹配 | 部分可审=中 |
| DB-19 | 异步与事务边界 | 异步任务是否假设继承调用方事务 / 连接；提交后投递是否用 afterCommit | 可审=高 |
