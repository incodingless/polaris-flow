## 为什么判据归本技能

判据单向流动：**建造侧 → 评审侧**（与 `prd` 族的 `refine → review` 同方向）。
`references/01-quality-criteria.md` 是 `§33` 五维质量审查清单 / `§34` 一票否决 31 条 / `§36` 最终判断标准的**唯一来源**；
建造侧 `references/07` 只留编号壳 + 指针，**编号沿用**，所以约 40 处既有引用未因迁移失效。

## 三环节定型后的改动（2026-09-15）

1. **删除 `scripts/verify.mjs` 死副本**（连带空目录）。它是拆分时的防御性拷贝，但本技能全部文档口径都指向
   `polaris{{SKN_SPR}}prototype{{SKN_SPR}}build` 的执行体，evals 也从不执行它——**零引用**。
   留着反而有害：`Step 2` 命令块写的是相对路径 `node scripts/verify.mjs …`，执行模型可能就近解析到本目录这份副本。
   删掉后单源自然恢复（对应此前登记的 S1）。

2. **新增取证源 E2**：经人工确认的《原型蓝图》。它把「原型是否符合已确认的设计」从**被评审者自述**（E3）
   升级为**需求方已背书的事实**（E2），但**仍顶替不了 E1**（需求方原始意图）。

3. **取证源等级改用 `E1`–`E5`**。原因：本技能里 `L1`–`L3` 早已被**三层验证**（静态 / 冒烟 / 黄金流）占用，
   两套坐标系同名字会写错报告。现声明：*`E` = 取证源，`L` = 验证层，不得互换*。

4. 输入契约表补第 4 行（经人工确认的蓝图，强烈建议）；交付物第 1 项的取证源清单改为 `E1`–`E5`。
5. 章节编号 `六 / 七 / 八` → `五 / 六 / 七`（此前 `四` 之后直接跳到 `六`，空号已补齐）。
6. version 1.2.1 → 1.3.0。

## 两条不能破的边界

- **只评不改**：本技能不改原型一行；发现的问题以「分级清单 + 定位证据 + 整改建议」给出。
- **独立性如实标注**：入口 B（流程移交）常在同一会话内由建造者接着执行，此时评审者 = 建造者。
  报告须注明，**但不因此放宽任何判据或降低等级**。
