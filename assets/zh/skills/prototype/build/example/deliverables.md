> 本文件是 `example/requirement.md` 的**输出**，演示 6+1 交付物实际长什么样（见 `references/04 §32`）。
> 真实项目里这 6 份文档通常分成多个文件；此处压在一个文件里，是为了让「输入 → 输出」对照可读。
> 第 7 项《高保真可交互 Web 原型》落在 `example/prototype.html`。

## ① Web 原型任务理解卡

| 项 | 内容 |
|---|---|
| 服务对象 | 法务专员（主）、合同管理员、业务发起人（次） |
| 核心痛点 | 人工逐条比对模板，单份 40 分钟，条款风险会漏检 |
| 一期目标 | 把「机械比对」交给系统，法务只做判断；漏检为 0 优先于省时间 |
| 成功标准 | 单份初审耗时下降；AI 结论必须可回溯到规则编号与命中位置 |
| 一期不做 | 模板管理、审批流配置、报表导出、移动端、对外分享 |
| 硬约束 | 不上传真实合同；演示数据脱敏；条款依据不得编造 |

## ② 核心用户任务流（黄金任务流）

> 法务在工作台看到「待我处理 12 份」 → 进入合同列表筛出高风险 → 打开其中一份 →
> 运行 AI 初审 → 看到 4 条风险条款及其依据 → 逐条确认 → 给出「通过」结论并归档。

链路四段：**发现待办 → 定位合同 → 机审取依据 → 人工下结论**。
每一段都有独立完成判据，任务流可断点续做（法务常被打断）。

## ③ Web 产品信息架构（IA）

```
合同审核台
├─ 工作台        待办队列 + AI 执行概况 + 我的进度
├─ 合同列表      全员/我的合同，按风险与状态筛选
├─ 合同审核      单份合同：条款清单 / 条款原文 / AI 结论 / 人工确认
└─ 新建送审      上传 → 填信息 → 提交
```

侧栏只放 4 个一级入口，深一层都用「主从式」在同一页内完成，不做三级菜单。

## ④ Web 页面清单与页面职责说明

| 页面 | 唯一职责 | 明确不负责 | 优先级 |
|---|---|---|---|
| 工作台 | 回答「我现在该做哪一份」 | 不放明细、不做审核动作 | P0 |
| 合同列表 | 回答「这批合同里哪几份要处理」 | 不做条款级展示 | P0 |
| 合同审核 | 回答「这份能不能过、依据是什么」 | 不承担批量操作 | P0 |
| 新建送审 | 把一份合同送进队列 | 不做审核 | P1 |

**页面必要性说明**：没有单独做「审核结果页」——结论与依据必须和条款原文同屏，否则法务要在两页之间来回对照；
也没有做「设置页」（一期无配置项）。这两处都是「为了显得完整而堆页面」的高发区，明确不做。

## ⑤ 页面结构、状态与交互说明

### 关键页面：合同审核

| 区块 | 内容 | 交互 |
|---|---|---|
| 头部 | 合同名 / 编号 / 相对方 / 金额 / 送审时间 + 状态徽标 | 状态徽标随确认动作变化 |
| 左栏 | 条款清单 12 条，风险条款带标记 | 点击切换中间栏原文 |
| 中栏 | 命中条款原文（只展示命中段落）+ 命中规则与位置 | — |
| 右栏 | AI 初审：未运行 / 处理中 / 完整结论 / 部分成功 / 服务不可用 | 「运行 AI 初审」触发 |
| 底栏 | 人工确认：通过并归档 / 驳回并退回 | 只有人工确认才写审核记录 |

### 11 种状态覆盖（在原型里逐个可切换，见 `?demo=1` 演示浮层）

| 状态 | 落点 | 关键要求 |
|---|---|---|
| Initial | 四页默认态 | 有内容、有主操作 |
| Loading | 工作台、合同列表 | 骨架屏 + 说明「通常 1 秒内返回」，不是干转圈 |
| Skeleton | 列表、KPI 卡 | 与真实布局同尺寸，避免跳版 |
| Empty | 合同列表 | 说明原因 + 给出口（清空筛选） |
| Error | 列表加载失败 / 上传解析失败 / AI 服务不可用 | 必须带错误码 + 下一步（重试 / 转人工 / 换文件） |
| AI Processing | 审核页 | 显示「正在解析条款 / 检索规则库 / 比对历史案例 / 生成结论」，而非只转圈 |
| Partial Success | 审核页 | 已判定的有效，未覆盖的明确交回人工，不静默跳过 |
| Human Review | 审核页底栏 + 列表「人工复核中」 | AI 只给参考，结论必须人工确认 |
| Success | 审核页归档卡 + 新建送审提交成功 | 展示结论、确认人、记录号 |
| No Permission | 工作台 / 列表 / 审核页 | 说清是哪个数据域受限 + 申请入口，不是「403」 |
| Disabled | 新建送审提交按钮、上一页 | 说明为什么禁用（四项必填），不是灰着不说话 |

## ⑥ 研发交接说明

**字段口径**

| 字段 | 来源 | 说明 |
|---|---|---|
| 合同编号 | 合同服务 | 格式 `HT-<年>-<4 位序号>`，全局唯一 |
| 风险等级 | AI 初审聚合 | 取最高风险条款等级；置信度 < 0.8 不计入自动等级，转人工 |
| 审核状态 | 审核记录 | 待审核 / 待运行 AI / 人工复核中 / 已通过 / 已驳回 |
| 审核记录号 | 审核服务 | `AR-<合同编号>-<序号>`，一次确认生成一条 |

**状态流转**

`待审核` →（运行 AI）`人工复核中` →（确认通过）`已通过` / →（驳回）`已驳回`
AI 调用失败不改变状态，只追加一条失败记录，可重试或转人工。

**AI 调用与兜底**

| 场景 | 行为 |
|---|---|
| 规则库超时（AI-RULE-SVC-503） | 界面给「重试 / 转人工」两个出口，不阻塞人工审核 |
| 规则库未覆盖某条款 | 归入「部分成功」，该条款标记为需人工比对，并给出应参照的指引文件名 |
| 置信度 < 0.8 | 不下风险结论，只作为「值得关注」提示 |

**响应式规则**：1366×768 为最小档，主从三栏降为两栏（条款清单压缩至 210px）；
列表宽表用容器内横向滚动，页面本身不横向溢出；1920×1080 下不做内容拉伸，靠容器最大宽度收敛。

**需求追踪**：需求包第 5 节「核心任务」对应黄金任务流 `example/flow.json`，可执行验证；
需求包第 4 节「一期范围」的四项，与页面清单一一对应；「不做」清单不出现在原型里。

node scripts/verify.mjs example/prototype.html --flow=example/flow.json --strict
