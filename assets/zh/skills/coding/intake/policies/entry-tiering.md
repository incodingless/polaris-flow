# 入口粗判（intake 私有）

> **这是 `intake`（任务管理与调度层）的私有细则**，`intake` 是其唯一调用方（调用位置 = 它的 Step 2 入口判档）。
> ⚠️ **本文随 `intake` 安装**（落在 `coding/intake/policies/`），**不再被注入其他技能**——别处写 `./policies/entry-tiering.md` 是坏引用。
> 本处只判**幅度轴 + 风险一票**，深度轴不可判（入口只有需求原文，无 `intention.md`）。

## 一、幅度轴（与 specify 的 `implementation-complexity.md` §二 同源）

| 档 | 判据 | 例 |
|---|---|---|
| **点** | 参数 / 文案 / 样式 / 日志，单文件单模块 | 改超时、改提示语 |
| **线** | 单功能 / 单条规则，一个模块内 | 加校验、改一处状态流转 |
| **面** | 多模块 / 多场景 / 新增完整流程 | 新增导出、跨模块联调 |
| **体** | 重构主干 / 新增跨模块核心能力 | 重构用户体系、引入新架构 |

## 二、风险一票（与 specify 的 `implementation-complexity.md` §四 同源）

命中即 `critical`：

- 资金 / 支付 / 结算 / 财务
- 合规 / 监管（强监管，违规有法律风险）
- 安全 / 鉴权 / 权限
- 不可回滚 / 回滚成本极高
- 存量数据迁移 / 数据丢失风险

## 三、入口粗判规则

- 幅度 = 点 / 线，且需求原文明确「表层」（改文案 / 样式 / 日志 / 参数）→ `trivial`
- 幅度 = 面 / 体，或命中风险一票 → `critical`
- 其余（深度不明 / 幅度不明）→ `standard`（**宁严**）

> 本处只判「选哪个入口技能」；**权威判档在 `specify` 出口**（那里有 `intention.md`，深度可判）。
> 深度不确定宁严落 `standard`，避免「改核心模块的单字段」被入口轻判 trivial。
> ⚠️ 幅度轴 / 风险定义与 specify 的 `implementation-complexity.md` §二 / §四 **同源**，改动需同步（本文件不另起一份定义）。
