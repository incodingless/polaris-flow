# design-template.md 模板（plan 阶段 · 高层设计）

> **使用约定**：由 `polaris{{SKN_SPR}}coding{{SKN_SPR}}plan` Step 4.2 组装输入时读取，Step 4.4 按 `./policies/artifact-batch-generation.md` 的 `design` 批次生成，落盘到 `openspec/changes/<change_id>/design.md`；Step 5.1 机械终检按本模板的节名与节序校验。

> **本阶段深度边界**：只写高层方案（架构决策、模块 / 领域划分、模块间接口契约、数据流）。**禁止**写到 `detailed-design.md` 或 `<slug>-design.md` 专项设计的粒度——实现级细节归 `design` 阶段；确需实现级设计时走 Step 6.1 深化设计决策点。
>
> **节名与编号约定**：节名一律中文，与 Step 5.1 机械终检同源；三个必含节的措辞不得改写，编号连续（新增节只在末尾顺延）。**唯一例外**：`## 0. 核心结论` 为前置结论节，固定置于 `## 1. 概述` 之前，不计入末尾顺延。

## 强制规则

1. **必含节**：`## 2. 前提`、`## 3. 原则与依据`、`## 5. 未选方案及拒绝理由`——措辞原样保留，缺任一 → Step 5.1 机械终检阻断
2. **节名与编号**：不得改动节名措辞与编号顺序；新增节一律追加到末尾并顺延编号（`## 0. 核心结论` 为唯一前置例外）
3. **结论前置**：`## 0. 核心结论` 的「核心架构决策清单」与「核心风险清单」两表必须非空，禁止只写正文不填前置结论
4. **深度上限 + 粒度红线**：写到契约级（谁调谁、传什么、什么时序），不写实现级伪码；**禁止**出现表字段、具体错误码、方法名 / 类名；`### 4.9` 只列「接口存在性契约」（路径 / 方法），字段级契约交 `design` 阶段 restful-api 专项
5. **候选方案量化对比**：`## 5.1` 必须给 ≥2 方案 ×（性能 / 成本 / 复杂度 / 交付周期 / 运维门槛）5 维量化对比 + 推荐依据；每个未选方案在 `## 5.2` 附「背景 / 选型理由 / 取舍权衡」
6. **风险三件套**：`### 4.11` 必须覆盖「过度设计风险 / 首版遗漏风险 / 最可能重构的部分」三项
7. **业务-技术映射**：`### 4.12` 每个技术组件必须标注业务场景与业务价值，禁止无锚点堆砌
8. **数据流闭环**：`### 4.6` 必须覆盖失败 / 降级 / 熔断分支，禁止只画正向主流程
9. **模板变量**：正文中所有 `{{...}}` 必须在生成时替换为真实值，不得原样留空
10. **防幻觉溯源**：技术特性、版本能力、性能数据必须标注来源，禁止「经测试满足」「已验证可支撑」等未证实结论；拿不准的标 TBD 或「待人工核验」
