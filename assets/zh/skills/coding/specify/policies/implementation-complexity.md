# 实现复杂度两轴判定（coding 族）

> **这是 `specify`（阶段 1：澄清）的私有细则**，`specify` 是其唯一调用方（调用位置 = 它的 Step 5.5 出口权威判档）。
> ⚠️ **本文随 `specify` 安装**（落在 `coding/specify/policies/`），**不再被注入其他技能**——别处写 `./policies/implementation-complexity.md` 是坏引用。
> **为什么私有不放顶层**：本模型只服务 coding 族的判档，放顶层 `policies/` 会被注入 debug / prd / prototype / testing 等无关族，属污染。
> **为什么另立文件**：`risk-signals` 是「实现侧事实信号清单」，没有「从需求推演实现复杂度」的两轴结构——只判到幅度（单字段），判不到深度（落在哪），于是「改核心结算模块的一个字段」被当成「简单功能优化」误判 normal。
> **迁移状态**：本文件已取代 `risk-signals.md` 原 §3 降档门 + §4 升档信号（两者已退役）；档位映射、glob 兜底、`current_tier` 合成保留在 `risk-signals.md`（§1 / §3 / §4）。

## 一、模型

```
实现复杂度 = 变更幅度(需求侧可判) × 落点深度(实现侧可判) ＋ 风险一票
```

- **幅度**回答「改多少」——需求原文即可判，需求复杂度（角色/场景/流程/规则）是它的输入。
- **深度**回答「改在哪」——从 `intention.md`（任务范围 / 下游约束 / 结论节）判；`tweak` 档经 lite-clarify L1 读代码，判得更准。
- **风险一票**：命中即 critical，不看两轴结果。
- **乘法而非加法**：幅度小但落点深，复杂度暴增。

## 二、幅度轴（需求侧 · 入口可判）

| 档 | 判据 | 例 |
|---|---|---|
| **点** | 参数 / 文案 / 样式 / 日志，单文件单模块 | 改超时、改提示语 |
| **线** | 单功能 / 单条规则，一个模块内 | 加校验、改一处状态流转 |
| **面** | 多模块 / 多场景 / 新增完整流程 | 新增导出、跨模块联调 |
| **体** | 重构主干 / 新增跨模块核心能力 | 重构用户体系、引入新架构 |

## 三、深度轴（实现侧 · 从 intention.md 可判）

| 档 | 判据（intention.md 的任务范围 / 下游约束 / 结论节） | 例 |
|---|---|---|
| **表层** | 只改 UI / 展示 / 独立工具，无下游依赖 | 改页面样式 |
| **逻辑** | 改业务规则 / 状态流转，无数据与契约变更 | 改结算规则、改状态机 |
| **结构** | 改数据模型 / 接口契约 / 领域模型 | 加字段、改接口签名 |
| **核心链路** | 改核心生产链路 / 主流程 / 核心数据流转，下游影响面广 | 改主流程编排、改核心算法 |

## 四、风险一票（命中即 critical，不看两轴）

- 资金 / 支付 / 结算 / 财务
- 合规 / 监管（强监管，违规有法律风险）
- 安全 / 鉴权 / 权限
- 不可回滚 / 回滚成本极高
- 存量数据迁移 / 数据丢失风险

> 机械兜底（路径片段 glob）沿用 `./policies/risk-signals.md` §3，与本节的「语义风险」互补。

## 五、合成矩阵（幅度 × 深度 → 档位）

| 幅度＼深度 | 表层 | 逻辑 | 结构 | 核心链路 |
|---|---|---|---|---|
| **点** | trivial | trivial | standard | critical |
| **线** | trivial | standard | standard | critical |
| **面** | standard | standard | critical | critical |
| **体** | critical | critical | critical | critical |

- 风险一票命中 → 一律 critical（覆盖矩阵结果）。
- 档位映射（trivial→tweak 等）沿用 `./policies/risk-signals.md` §1。

## 六、消费切片（三技能各司其职）

| 判定点 | 判什么 | 判据来源 |
|---|---|---|
| `specify` Step 5.5（出口权威判档） | **幅度 × 深度 + 风险一票** | 本文件 §二~§五（唯一调用方） |
| `intake` Step 2（入口粗判） | 只判幅度轴（深度未知） | `intake/policies/entry-tiering.md`（与本文件 §二/§四 同源） |
| `verify` Step 9（复核） | 真实 diff 复核深度 + 风险 | `verify/policies/complexity-review.md`（与本文件 §三/§四 同源） |

> 三处判据「同源不同载体」：本文件是完整模型的唯一源；intake / verify 各持自己需要的那一轴，
> 并在各自文件头标注「与本文件同源、改动需同步」。深度轴需 `intention.md`（入口没有）才判得准，
> 故入口只判幅度、深度不确定宁严落 `standard`；权威判定在本文件消费方 `specify` 出口。
