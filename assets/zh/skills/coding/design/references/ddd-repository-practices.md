# DDD 仓储设计实践（精简参考）

> **用途**：供 `design-repository-policy` 在生成 `repository-design.md` 时 `read_file`。  
> **定位**：划分与自检清单，**不是**需求来源。仓储对象与操作必须来自 `domain-model-design.md`（唯一领域概念源）。  
> **禁止**：把本文件范例仓储名直接抄进当前变更；禁止在此参考指导下产出 SQL/ORM/DDL。

---

## 1. 仓储是什么（工作定义）

仓储（Repository）是**领域层看到的持久化抽象**：按**聚合**存取，隐藏表/文档/缓存细节。  
它不是：通用 DAO、任意 SQL 垃圾桶、应用层流程脚本。

```text
领域行为 → 仓储（聚合进出）→ 基础设施（ORM/SQL/驱动）
                ↓
         data-model-design（表形状）
```

---

## 2. 划分规则

| 规则 | 说明 |
|------|------|
| **一聚合一根仓储（默认）** | `OrderRepository` 只管 Order 聚合；不通过该仓储改 Customer 内部 |
| **按聚合根命名** | `{AggregateRoot}Repository`；禁止 `XxxManager` / `XxxDao` 混称 |
| **跨聚合** | 应用服务或领域服务编排多个仓储；**不**在一个仓储里隐式写多个聚合 |
| **不要「上帝仓储」** | 全系统一个 `AppRepository` → 拆回按聚合 |

例外（须在设计中写明理由）：只读查询仓储、跨聚合报表端口——与写模型仓储分开，避免污染聚合边界。

---

## 3. 方法集最佳实践

**写模型仓储（默认应有）**

| 方法意图 | 说明 |
|----------|------|
| `save(aggregate)` / `add` | 新建或更新整个聚合（由实现决定 insert/update） |
| `findById(id)` | 取回完整聚合（或明确的加载策略） |
| `remove(aggregate)` / `delete` | 按领域规则删除或标记删除 |

**按场景追加**（每条须有 specs / detailed-design 依据）

- `findByXxx`：领域命令路径上的定位查询（如按业务单号取根）
- `exists` / 唯一性检查：支撑不变式，而非 UI 列表
- 批量：仅当领域明确批量命令；注意事务与性能

**避免**

- 上百个细粒度 `updateFieldA`（破坏聚合封装）
- 返回未受根保护的内部实体集合供外部随意改
- 在仓储接口上暴露 `Connection` / `EntityManager` / 原生 SQL

---

## 4. 事务与一致性

1. **一个业务命令 ≈ 一个聚合上的一次事务**（默认）  
2. **跨聚合强一致**：优先质疑划分；若必须，在设计中写明分布式事务/共享库事务的代价  
3. **跨聚合最终一致**：领域事件 + 发件箱/消费方仓储更新；写清「谁存事件、谁保证至少一次」  
4. **工作单元（Unit of Work）**：若项目采用，说明与仓储的关系（谁提交、谁回滚）；不采用则写「显式 save + 事务边界在应用服务」

---

## 5. 查询：写模型 vs 读模型

| 类型 | 放哪 | 例子 |
|------|------|------|
| 为执行命令而定位聚合 | 写模型仓储 | `findById`、`findByOrderNo` |
| 列表、筛选、报表、联表投影 | 读模型 / 查询服务（可另端口） | 管理端分页订单列表 |
| CQRS 已选型 | 读写分离在设计中显式画清 | detailed-design 已定再写 |

不要把所有 `SELECT` 塞进写模型仓储「图省事」。

---

## 6. 并发、幂等、缓存

- **乐观并发**：聚合版本号 / `updated_at` 条件更新；冲突时领域如何表现（重试 / 报错）  
- **幂等**：同一命令重复到达时仓储侧如何不双写（幂等键表、自然业务键）——有依据才写  
- **缓存**：只缓存能说清失效策略的读；默认不在仓储接口上假装「自动缓存一切」

---

## 7. 与领域事件

- 仓储在 `save` 成功后**不负责**业务决策；事件的收集可在聚合内，发布在应用/基础设施  
- 若用**事务性发件箱**：在仓储设计中点名「与聚合同事务写入 outbox」，细节可留给 data-model / 基础设施专节  
- 禁止：仓储方法里写「调用外部 HTTP 发事件」而不谈失败与一致性

---

## 8. 生成后自检

| # | 检查项 | 失败时 |
|---|--------|--------|
| R1 | 每个仓储对应且仅对应一个写模型聚合根（或已声明例外） | 拆分或改名 |
| R2 | 每个方法能指回领域行为或验收场景 | 删除或标 TBD |
| R3 | 无字段级 DDL / 完整 ER（应在 data-model） | 挪出 |
| R4 | 跨聚合写入有显式编排说明，非隐藏在单仓储 | 改应用/领域服务编排 |
| R5 | 列表类重查询未伪装成写模型仓储核心 API | 迁到读模型节 |
| R6 | 与 domain-model §9 / 实体列表无矛盾 | 先对齐领域模型 |
| R7 | 事务、并发、事件至少各有一句可评审表述（或显式 N/A） | 补全 |
