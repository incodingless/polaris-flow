# 测试用例清单标准（场景枚举判据）

> 归属：`polaris{{SKN_SPR}}coding{{SKN_SPR}}tasks` 技能。  
> **两个读者**：① 主代理在 Step 4 写 TDD 任务时，作为「写失败测试」**之前**的场景枚举判据；② `tasks-review-agent` 在 Section 3 测试评审时，用同一套分类语言**反查**清单完整性。  
> 本文档是**场景分类的唯一语言**；`test-review-methodology.md` 的审计口径（覆盖图 / ★评分 / 缺口）复用本文档的分类，不另起一套。

## 一、为什么必须枚举

AI 写测试有「主路径偏好」：拿到「写失败测试」四个字，会直接写 happy path，分支 / 异常 / 边界 / 依赖失败天然被漏掉。枚举把「写测试」从**一个动作**升级为**先穷举场景、再映射代码**，用固定维度强制补齐，而非依赖临场发挥。

## 二、场景分类（6 大类）

| 分类 | 定义 | 覆盖目的 |
|------|------|----------|
| 正常路径 | 合法输入、标准流程、主业务分支 | 核心功能正确性 |
| 边界值 | 数值 / 长度 / 集合的临界值、空值、零值、极值 | 捕获边界逻辑错误 |
| 异常输入 | 非法参数、格式错误、违反校验规则的入参 | 验证参数校验逻辑 |
| 依赖异常 | 外部依赖失败、超时、返回空 / 错误、抛异常 | 验证容错与降级 |
| 状态校验 | 对象处于不同状态下的操作行为 | 验证状态机流转规则 |
| 幂等/并发 | 重复调用、重复提交、并发请求 | 验证幂等性与线程安全 |

### 适配规则（不硬强制 6 类）

按**被测对象类型**裁剪强制范围，避免为纯函数硬编无关用例（YAGNI）。**无对应场景必须显式标注「无」，不得静默跳过。**

| 对象类型 | 强制覆盖 | 标注「无」 |
|----------|----------|-----------|
| 纯函数 / 工具方法 | 正常路径、边界值、异常输入 | 依赖异常、状态校验、幂等/并发 |
| 含外部依赖的服务方法 | 正常路径、边界值、异常输入、依赖异常 | 状态校验、幂等/并发 |
| 带状态的对象 / 状态机 | 正常路径、边界值、异常输入、状态校验 | 依赖异常、幂等/并发 |
| 有副作用 / 可重复提交的方法 | 正常路径、边界值、异常输入、幂等/并发 | 依赖异常、状态校验 |

## 三、优先级

| 级别 | 定义 |
|------|------|
| **P0（核心必测）** | 核心业务路径、核心异常、主校验规则；不通过则功能不可用 |
| **P1（分支必测）** | 所有边界值、全部分支异常、所有状态流转；不通过则存在质量风险 |
| **P2（边缘场景）** | 极端输入、非核心规则、小众异常；不影响主流程可用性 |

## 四、Given-When-Then 句式（可映射 AAA）

每条用例统一「给定[条件]，当[执行操作]时，应[预期结果]」，且可直接映射为 AAA：

| 结构 | 拆解 | 对应 AAA |
|------|------|----------|
| Given（前置） | 初始数据状态、外部依赖 Mock 行为、环境配置 | Arrange |
| When（操作） | 被测方法 + 入参值 / 入参范围 | Act |
| Then（结果） | 返回值 / 异常（类型+关键信息）/ 内部状态变化 / 依赖调用（次数+参数） | Assert |

预期结果必须**可量化、可断言**，禁止「正确」「正常」等模糊表述。

## 五、一条用例只验证一个行为点

每条用例只覆盖一个分支、一个可定位的失败原因；多分支堆砌会导致失败后无法定位问题。

## 六、反模式（禁止）

1. **粒度太粗**：只写「测试 X 功能」，未细化到具体输入与输出
2. **预期模糊**：写「返回正确结果」，无法生成有效断言
3. **分类缺失**：只有正常路径，缺异常 / 边界 / 依赖失败场景
4. **多行为堆砌**：一条用例同时验证多个分支
5. **实现导向**：描述内部实现而非外部行为，导致测试脆弱

## 七、内联清单格式（写进 tasks.md 的 TDD 任务）

清单作为**内容块**内联在 TDD 任务的 Files / Interfaces 之后、子步骤之前，用**场景级精简表格**（每场景一行），**不带 checkbox**——它是 tasks 阶段的枚举产物，不是 implementer 的待办。完整断言细节由 implementer 在写测试时展开。

```markdown
- [ ] 1.1 {{TASK_NAME}}  <!-- TDD 任务 -->

  **用例清单**（tasks 阶段枚举）：
  | ID | 分类 | 场景（Given-When-Then） | 优先级 |
  |----|------|--------------------------|--------|
  | UC1 | 正常路径 | 给定合法 dto，当调用 createUser 时，应返回用户 ID > 0 且 save 调用 1 次 | P0 |
  | UC2 | 边界值 | 给定密码长度=6（下限），当调用 createUser 时，应注册成功 | P1 |
  | UC3 | 边界值 | 给定密码长度=5（越下限），当调用 createUser 时，应抛参数异常且 save 调用 0 次 | P1 |
  | UC4 | 异常输入 | 给定手机号格式非法，当调用 createUser 时，应抛参数异常含「手机号格式错误」 | P1 |
  | UC5 | 依赖异常 | 给定 save 抛 SQLTimeoutException，当调用 createUser 时，应抛系统异常且异常链含超时 | P0 |
  | UC6 | 幂等/并发 | 给定重复提交相同 dto，当连续调用两次时，应只创建一次且第二次抛业务异常 | P2 |
  | — | 状态校验 | 无（本方法无状态） | — |

  - [ ] 1.1.1 按清单写失败测试：`{{TEST_PATH}}`
```

要点：

- **ID** 用 `UC+序号`，跨任务全局唯一或按任务前缀区分（如 `1.1-UC1`）
- **分类**列须覆盖 6 大类；不适用的大类显式写「无」
- **优先级**保证 P0 全核心路径、P1 全边界与分支
- 清单是「枚举产物」，可被 `tasks-review-agent` 反查；枚举不充分 = 测试缺口
