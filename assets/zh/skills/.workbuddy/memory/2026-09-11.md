## 三轮：核实「命令目录改下划线前缀能否躲过注册」（**推翻二轮的一个结论**）

**问题**：我上一轮建议「安装器跳过 `_` 前缀目录 + 把 `policies/` 改名 `_policies/`」。用户追问：改下划线后 Trae 等平台会不会仍自动识别成命令？

**答案：会。改名挡不住，两层都挡不住。**

**第一层 — 我们自己的安装器根本不认下划线**（这次逐行核实）：
- `src/utils/file-system.ts:87-111 walkFilesSafe` = 纯递归，`if (entry.isDirectory()) walk() else push()`，**零过滤**（连 dotfile 都不跳）
- `src/core/install/commands.ts:57-71` 直接把 `commands/` 下每个文件的 `shortPath` 落盘，**不查任何跳过规则**
- `src/core/assets/layout.ts:50 shouldSkipAsset` **确实有**跳过机制，但只服务 skills 域安装，按 `skills/backup/`、`skills/requirements-engineering/`、`/.workbuddy/` 前缀判断 → **commands 安装路径完全不调用它**
- 结论：`_policies/complexity-router.md` 会照旧落盘 → 改名在安装阶段零效果

**第二层 — 三个平台官方文档都没有「下划线前缀豁免」规则**（外部取证）：
- **Trae**（docs.trae.ai/ide/slash-commands）：`.trae/commands` **支持最多 3 层嵌套**（v3.5.56, 2026-05 起；文档给了完整树示例）。`_policies/` 是第 1 层 → **在识别范围内**。无任何前缀排除条款
- **Cursor**：官方人员论坛回复（2026-03）—— **IDE 递归扫描 `.cursor/commands/` 子目录**；**CLI 只读顶层、完全跳过子目录**。无下划线规则
- **Claude Code**（code.claude.com/docs/en/slash-commands）：`.claude/commands/frontend/component.md` → `/frontend:component`，递归 + `:` 命名空间。文档中**唯一**的「跳过」只针对保留名 `synced` 与名称冲突，与 `_`/`.` 无关

**⚠️ 推翻二轮的错误结论**：二轮据 `src/core/integrations/openspec.ts:267` 注释断言「**Trae 走扁平命令名**」。**这是错的/过时的** —— Trae 官方文档明确支持 3 层嵌套；OpenSpec 用扁平 `opsx-*` 是它自己的兼容选择，不代表 Trae 能力上限。即：Trae **不是**因为不支持嵌套才扁平，我之前据此推出的「Cursor/Trae 侧大概率失效」需要重新评估（Cursor CLI 确实只读顶层，Cursor IDE 与 Trae 都支持嵌套）。

**⚠️ 第二个自我更正**：二轮/三轮初判 `commands/policies/complexity-router.md` 是「孤儿文件」——**错**。`flow.md:148` 有引用：「按 `policies/complexity-router.md` 跑 3 档评估」。它是 flow.md 的**同位伴生资源**（刻意放在 `commands/policies/` 以便相对路径可达）。earlier grep 漏看是因为 `head_limit:30` 截断。

**由此暴露的真正问题（比"多一个垃圾命令"严重）**：在这几个宿主里，「文件出现在 `commands/` 下」**就是**注册机制，没有独立的注册步骤。所以给安装器加下划线过滤 ≠「藏起来」，而是**等于删掉**。而 flow.md:148 依赖该文件 → **引用断链**。所以下划线方案不只是"无效"，而是**不成立**（两个诉求无法靠改名同时满足）。

**旁证：命令引用策略的既有惯例**：`flow.md:30` 写「与共享策略 `policies/ask-question-react.md` 保持一致」，而该文件真实位置是 `assets/zh/policies/ask-question-react.md`（属 `PACKAGE_COMMON_PREFIXES`，落 `plugin_root/policies/`）。即**命令体重引用共享策略用裸路径 `policies/<name>.md`**，指的是语言包顶层 policies。

**候选解法（待用户定）**：
- **A 内联**：把 `complexity-router.md` 内容并入 `flow.md` 0.4 节（其自述就是"命令文件的内联策略，不被任何 skill 调用"），删文件 → 零外部依赖、零平台风险；代价 flow.md 由 372 行长到约 450 行
- **B 移到 `assets/zh/policies/`**：引用串 `policies/complexity-router.md` **一个字都不用改**（与 flow.md:30 惯例自洽）→ 不再进 commands 树、不会注册成命令；代价：`skills.ts` Step 3 会把顶层 policies **注入每个叶技能的 `policies/`**，多一份重复分发

**方法教训**：本机 BSD grep 的 `\|` BRE 交替**同样失效**（不只是 `\b`）→ 一律改用 Grep 工具；且 `head_limit` 会静默截断导致「误判为无引用」。
