## GSD 框架集成方案（仅方案，待拍板）

用户要求为 Coding、PRD 工作流集成 GSD（get-shit-done-cc）框架并制定项目宪法。

### 核心判断

- polaris 已有大量 GSD 等价物：OpenSpec 四件套 ≈ PROJECT/REQUIREMENTS/ROADMAP、state.yaml/workflow.yaml ≈ STATE.md、tweak ≈ quick、clarify ≈ discuss-phase。**不安装 GSD 原生包**（双规格体系冲突 + 命令族重复 + `--dangerously-skip-permissions` 不引入），只吸收机制。
- 建议吸收 4 项：①原子任务 + 每任务新上下文（子代理）执行，落 build，顺带修复 subagent-delegate-policy 幽灵引用；②Wave 依赖并行，tasks 模板加 depends/wave 列；③原子提交（一任务一 commit，可 bisect）；④UAT 互动验收，verify 扩展 constitution-audit 产出 UAT 报告进 reviews/。
- PRD 侧：clarify ≈ discuss（灰色地带提问）、draft.key_points ≈ CONTEXT.md 决策锁定、review 吸收 GSD plan_check 强化 cross_check_report，**不新增阶段**。

### 宪法方案

复用已有基础设施：constitution 技能（CREATE/AMEND/SHOW）+ constitution-validity 机器校验（占位符/`## Core Principles`/`**Version**:`）+ 注入点 A/B/C/D。新增 5 条 Core Principles：规格先行、原子任务、上下文隔离、原子提交、验证闭环；NON-NEGOTIABLE 标记须经用户显式确认（HARD-GATE）。P01/tweak 建议豁免原子提交/子代理强制项（流程税）。

### 实施顺序（待确认后执行）

Phase 1 宪法起草 → Phase 2 Coding（tasks 模板 + build 执行策略 + verify UAT）→ Phase 3 PRD 对齐 → Phase 4 文档/安装器收尾。
