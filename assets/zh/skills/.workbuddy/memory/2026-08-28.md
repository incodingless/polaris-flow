## subagent-dispatch 引入 agent_mode 区分通用/专用两种派发模式

**背景**：用户指出有两种派发需求——(1) general：只要独立上下文执行，不要求专用 agent；(2) specialized：必须用专用 agent，不存在则退化 inline 并询问用户确认（inline 直接 / 先压缩上下文再 inline / 中止）。

**改动文件**：
- `subagent-dispatch/SKILL.md`：task_spec 加 agent_mode 字段（general/specialized）；输出结构加 needs_inline_confirmation 状态 + inline_options 字段；degradation 加 needs_confirmation 值；完整流程加 [4a]/[4b] 分支；加二次调用机制（constraints 传 inline_decision）
- `subagent-dispatch/references/degradation.md`：决策矩阵加 agent_mode 列和 needs_confirmation 行；加 needs_confirmation 详细流程；加 general 模式回退链；硬约束更新；示例加 specialized 场景
- `subagent-dispatch/references/task-type-mapping.md`：匹配算法 [0] subagent_id 未命中时按 agent_mode 分支（specialized 不回退 → needs_confirmation，general 回退匹配）
- `subagent-dispatch/references/dispatch-execute.md`：输入参数表加 agent_mode 行，constraints 注明 specialized inline 确认后含 inline_decision
- `prd/refine/SKILL.md`：Step 3.1 和 3.2 的 task_spec 加 agent_mode=specialized；返回消费表加 needs_confirmation 行；加 specialized inline 确认流程；并行约束加 needs_confirmation 不阻塞说明；结果汇总加 abort 处理

**核心设计**：
- general 模式（默认）：subagent_id 未命中 → 回退 task_type 匹配 → 默认 subagent → inline（自动链式降级）
- specialized 模式：subagent_id 必填，未命中 → 不回退，返回 inline_options 让用户选（A:inline 直接 / B:先压缩再 inline / C:abort）
- 用户选择后二次调用 subagent-dispatch，constraints 传 inline_decision
- specialized 不自动回退的原因：专用 agent 承载特定评审方法/工具集，回退通用型会丢失专属性，产出质量不可控

## subagent-dispatch 拆分为 subagent-probe + subagent-dispatch

**背景**：用户要求把探测与派发拆开，让主技能（编排方）能根据探测结果做编排决策。

**新架构（三段式编排）**：
- `subagent-probe`（纯探测）：入参 platform + 可选 subagent_id / task_type；出参 agents[]（id/path/description/tools/task_types/source/selected）、subagent_id_found、matched_agents、platform_degradation（null/inline/unsupported）。不做任何决策；无 agent 级 degradation（agents 空是数据事实）
- `subagent-dispatch`（纯派发）：入参 platform + agent（probe 结果中调用方选定项，可 null）+ task_spec；agent=null 时按 constraints.dispatch_mode_hint 走 default_subagent 或 inline。出参 dispatch.status（dispatched/degraded_default/degraded_inline/unsupported）+ result
- 调用方（编排型技能，如 prd/refine）：probe 一次 → 自己选 agent / 判断降级 / 询问用户（AskUserQuestion 三选项：inline_direct / inline_after_compress / abort）→ dispatch 派发

**关键设计决策**：
- needs_confirmation/inline_options/二次调用机制全部删除——询问用户的 UX 上移到调用方，dispatch 无状态单次调用
- degradation 字段拆解：platform 级（probe 的 platform_degradation）+ agent 级（调用方判 agents 是否为空）+ 派发级（dispatch.status）
- probe 的 matched_agents 预筛（专精在前通用在后）——省事调用方直接取第一个
- references 归属：platform-probe.md + task-type-mapping.md → probe；dispatch-execute.md → dispatch；degradation.md 删除

**改动文件**：
- 新建 `subagent-probe/`（SKILL.md + references/platform-probe.md + references/task-type-mapping.md）
- 重写 `subagent-dispatch/SKILL.md`（瘦身，只剩派发）；references 只留 dispatch-execute.md（尾部改为 agent=null 两分支说明）
