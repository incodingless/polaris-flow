# idea-discovery 基线压力场景（红阶段）

编写 SKILL.md 前记录的「无技能」典型失败与合理化借口。绿阶段技能正文针对下列模式写最小反驳。

## 场景 1：模糊想法 + 「直接写代码吧」

- **压力：** 时间 + 用户权威
- **基线失败：** 跳过调研/澄清，直接实现
- **典型借口：** 「需求已经够清楚了」「先写起来再改」

## 场景 2：完整 PRD + 「别调研了」

- **压力：** 权威 + 效率
- **基线失败：** 跳过 Phase 0 代码/OpenSpec 交叉验证
- **典型借口：** 「文档里都有」「不用看代码」

## 场景 3：模糊点仅 1 个

- **压力：** 发散惯性
- **基线失败：** 对清晰项展开 3+ 方向
- **典型借口：** 「多发散几个方向更保险」

## 场景 4：用户称「很简单」

- **压力：** 权威 + 效率
- **基线失败：** 无调研证据标 simple，或跳过 brainstorm.md
- **典型借口：** 「用户说简单就标 simple」「simple 不用写文档」

## 场景 5：无 openspec CLI

- **压力：** 工具缺失
- **基线失败：** 以无法调研为由跳过 OpenSpec
- **典型借口：** 「没有 CLI 就跳过 OpenSpec」

## 场景 6：复杂多子系统需求

- **压力：** 范围模糊
- **基线失败：** 不拆分，一次覆盖全平台
- **典型借口：** 「一次讨论完更高效」

## 场景 7：OpenSpec change 已存在

- **压力：** 上下文干扰
- **基线失败：** 误读旧 artifact，不与用户确认
- **典型借口：** 「design.md 里已经写了，不用问」
