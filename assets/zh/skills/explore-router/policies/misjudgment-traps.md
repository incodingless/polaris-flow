# 常见误判陷阱与覆盖规则

## 用途

即使总分达到 SKIP 门槛，命中以下陷阱时也必须**降级路由**（SKIP→LIGHT，LIGHT→FULL）。这些陷阱来自实战案例，针对 Agent 与人类评审的常见盲区。

---

## 陷阱清单

### TRAP-1：篇幅幻觉

**信号**：文档篇幅长（>5 页或 >2000 字），但缺少排除项、异常场景、量化指标中的至少两项。

**典型表现**：
- 20 页 PRD 只描述正常主流程
- 有详细 UI 截图但无验收标准
- 功能列表很长但无优先级与排除项

**覆盖规则**：命中 → 路由降一级；若原判定为 LIGHT 且维度 1 得分 ≤1 → 直接 FULL

**实战依据**：68% 工程返工请求追溯至缺失或模糊的验收标准（Scriptonia, 2026）；长文档不等于可测试规格。

---

### TRAP-2：形容词需求

**信号**：核心业务目标或 NFR 使用不可测试的形容词，且文档中无对应量化阈值。

**典型词汇**：「快速」「流畅」「体验好」「实时」「高效」「易用」「稳定」「无缝」

**对比**：
- ❌ 「导入要快」→ 0 分
- ✅ 「10,000 行 CSV 在 5 分钟内完成，每 10 秒更新进度」→ 可给分

**覆盖规则**：命中 ≥2 处形容词且无量化替代 → 路由降一级；核心目标（D1-1）使用形容词 → 维度 1 强制 ≤1 分

**实战依据**：IBI Smart 项目「实时」在 engineering（亚秒刷新）与 business（查看时更新）间定义分歧，若不在 explore 阶段澄清将导致架构返工。

---

### TRAP-3：只写 Happy Path

**信号**：验收标准仅覆盖正常流程，缺少错误处理、权限拒绝、空状态、超时、并发冲突等异常分支。

**典型表现**：
- GWT 场景全部以成功结束
- 无「When 用户无权限 Then …」类场景
- 异常场景占比明显低于 30% 或无法统计

**覆盖规则**：命中 → 路由降一级；维度 2 得分强制 ≤1 分

**实战依据**：Agent 不会像人类工程师那样主动追问模糊 AC，会直接猜测并实现——未写明的 unhappy path 必然被错误实现。

---

### TRAP-4：历史经验替代

**信号**：文档以「与上次类似」「参考 XX 项目」「沿用现有逻辑」替代本次范围确认，但未列出与历史方案的差异点。

**典型表现**：
- 「跟 v1 一样，加个字段」但未说明 v1 边界
- 「上次做过支付集成」但未确认本次支付渠道/回调差异
- 引用历史 PRD 但无 diff 说明

**覆盖规则**：命中 → 至少 LIGHT，不得 SKIP；在报告 `trap_flags` 中标注并列出需确认的差异点

**实战依据**：需求边界的微小差异可能导致实现方案完全不同；无 discovery 的项目常见 140-180% 范围膨胀。

---

### TRAP-5：业务清晰但技术盲区

**信号**：产品视角（用户故事、流程图）完整，但缺少模块/接口/数据表/依赖团队清单。

**典型表现**：
- 有精美用户旅程图但无系统影响面
- 未列出需变更的 API endpoint
- 未说明与哪些团队需联调

**覆盖规则**：命中 → 维度 3 得分强制 ≤1 分；路由降一级

**实战依据**：跳过 discovery 后集成失败、隐性耦合在开发中期才暴露，修复成本呈指数增长。

---

### TRAP-6：Agent 不可测试 AC

**信号**：验收标准无法转化为 pass/fail 判定——QA 和 Agent 无法据此写测试。

**典型表现**：
- 「功能正常工作」
- 「用户体验良好」
- 「Then 操作成功」无具体 UI/数据状态
- 一条 AC 包含多个独立判定（应拆分）

**覆盖规则**：命中 ≥2 条 → 维度 2 得分强制 ≤1 分；路由降一级

---

## 覆盖规则汇总

| 原路由 | 命中任一击穿陷阱 | 最终路由 |
|--------|-----------------|---------|
| SKIP | 是 | LIGHT（TRAP-1/2/3/5/6 严重时可升至 FULL） |
| LIGHT | 是 | FULL |
| FULL | — | 保持 FULL |

**L3 特殊规则**：无论分数多高，L3 变更**不得路由为 SKIP**（最多 LIGHT）。此规则优先于分数判定。

---

## 检测报告格式

在 `clarity-report.md` 的 `trap_flags` 节记录：

```markdown
## 误判陷阱检测

| 陷阱 ID | 命中 | 证据 |
|---------|------|------|
| TRAP-1 篇幅幻觉 | 是/否 | <引用或说明> |
| TRAP-2 形容词需求 | 是/否 | <引用或说明> |
| ... | ... | ... |

覆盖后路由调整：<原路由> → <最终路由>（原因：<陷阱 ID>）
```
