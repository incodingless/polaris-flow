## 附录 A：问题等级定义速查

| 等级 | 定义 | 处理要求 | 示例 |
|---|---|---|---|
| **P0 阻塞** | 影响业务逻辑正确性、范围完整性、可实现性的核心问题，不修复则需求无法进入开发 | 必须修复后才能定稿，修复后重新评审 | 核心业务场景遗漏、状态流转矛盾、关键规则缺失、与基线严重不一致 |
| **P1 重要** | 影响需求质量、可测试性、可维护性的问题，不修复会导致开发误解或测试遗漏 | 建议修复，如不修复需在评审报告中记录风险与接受理由 | 规则模糊、异常处理不完整、验收标准缺失、术语不一致 |
| **P2 一般** | 表述优化、格式规范、建议类问题，不影响需求核心逻辑 | 可选择性修复，不阻塞定稿 | 错别字、格式不统一、表述可优化、建议补充说明 |
| **P3 待确认** | 需要业务方或技术方决策的问题，当前无法判断是否为问题 | 列入待确认事项，明确决策人与决策时间 | 技术可行性待确认、业务规则待业务方决策、第三方依赖待确认 |

## 附录 B：评审结论判定标准

| 结论 | 条件 | 后续动作 |
|---|---|---|
| 通过 | P0 = 0 且 P1 = 0 | 可进入定稿流程 |
| 有条件通过 | P0 = 0 且 P1 > 0 | 需记录 P1 风险与接受理由后进入定稿流程 |
| 不通过 | P0 > 0 | 必须修复 P0 后重新评审，不可定稿 |

## 附录 C：重评审机制

| 项目 | 说明 |
|---|---|
| 触发条件 | 存在 P0 阻塞问题，或用户要求重评审 |
| 重评审范围 | 仅评审修复的问题及其关联内容，不重复评审已通过部分 |
| 重评审流程 | 用户确认修复 → 加载修复后文档 → 针对修复问题执行检查 → 确认是否真正修复、有无引入新问题 → 更新评审报告 |
| 迭代终止条件 | P0 阻塞问题清零，或用户确认接受剩余风险 |
