# 业务层模糊点识别与合理性校验

> discovery Step 4.1 的扫描清单与校验维度。SKILL `read_file` 本文件执行扫描，不内联副本。

## 一、业务层模糊点分级扫描

| 维度 | 检查要点 |
| -------------- | ------------------------------------------------------------------ |
| 冲突假设类 | 段落间互相矛盾之处 |
| 信息缺失类 | 五要素、5W2H 是否完整，核心输入输出是否明确 |
| 概念歧义类 | 是否存在主观形容词、量化模糊词、一词多义、未定义术语 |
| 边界范围类 | 功能边界、用户边界、数据边界、场景边界是否清晰，异常流程是否覆盖 |
| 隐含假设类 | 是否存在未言明的业务、数据、技术、使用假设 |
| 约束缺失类 | 时间、成本、性能、兼容性、合规等约束是否明确 |
| 优先级依赖类 | 多功能点优先级是否划分，与现有系统 / 功能的依赖关系是否清晰 |
| 缺口 | 缺状态机/权限/失败态/数据归属等 |

按复杂度决定扫描深度：

- 简单需求：扫描核心 3 维度（信息缺失、边界范围、约束缺失）
- 标准需求：全量 8 维度扫描，能通过现有资料补全的自动补全，无法补全的列入待澄清清单
- 复杂需求：全量 8 维度扫描 + 隐性约束深挖（记录原始需求未提及但高度相关的约束、规则、历史决策，单独归类标注来源）

## 二、必问项强制校验（业务层首次 + 终检）

硬性校验以下 6 项是否覆盖，未覆盖则自动补充为高优先级问题：

- 模块归属
- 核心范围边界（做 / 不做）
- 角色与权限边界
- 核心业务流程
- 数据指标与效果验证方式
- 配置模型 / 状态枚举验证（涉及现有配置修改时必查）

## 三、业务合理性校验

| 识别维度 | 检查点 |
|---|---|
| 实现必要性 | 区分**强痛点**（不做则无法推进）还是**痒点**（锦上添花）；高频普遍 vs 低频个别 |
| 业务合理性 | 是否符合业务逻辑，是否与现有规则冲突，是否重复建设，目标是否可验证 |
| 技术可行性 | 是否适配现有技术栈，是否依赖未开放能力，是否有明显性能瓶颈 |
| 合规性 | 是否满足数据安全、隐私保护、行业监管、内部制度要求 |
| 成本合理性 | 投入产出是否匹配，是否过度设计，是否有低成本替代方案 |

按复杂度决定校验深度：

- 简单需求：仅做业务合理性单点判断
- 标准 / 复杂需求：业务合理性、技术可行性、合规性、成本合理性四维度全量校验，存疑点列入待澄清清单
