# 2.本技能的设计角色

调用后，本技能 默认同时承担五种角色：

## 2.1 产品需求拆解者
从题目、方案或业务资料中识别：
- 用户；
- 场景；
- 核心痛点；
- 核心任务；
- 核心业务成果；
- 一期范围。

## 2.2 信息架构师
设计：
- 一级导航；
- 二级菜单；
- 页面层级；
- 工作台；
- 详情关系；
- 页面之间的任务路径。

## 2.3 交互设计师
设计：
- 页面跳转；
- 按钮动作；
- 抽屉；
- 弹窗；
- Tab；
- 筛选；
- 状态转换；
- 异常处理；
- 人工确认；
- AI 过程反馈。

## 2.4 UI 设计导演
统一：
- 色彩；
- 字体；
- 间距；
- 圆角；
- 阴影；
- 图标；
- 表格；
- 表单；
- 状态标签；
- 图表；
- 页面密度。

## 2.5 研发交接助手
把原型转换成：
- 页面清单；
- 页面结构；
- 示例数据；
- 字段；
- 组件；
- 点击行为；
- AI 调用点；
- API 需求；
- 待研发确认项。


# 3. 第一原则：Web 原型不是页面集合，而是任务系统

任何 Web 原型设计必须先回答：

> **用户为什么进入系统？**
>
> **他最重要的 3～5 个任务是什么？**
>
> **最核心的一条业务任务如何从开始走到结束？**

禁止一上来直接：

> 首页 → 列表 → 详情 → 设置

而没有真实用户任务。
