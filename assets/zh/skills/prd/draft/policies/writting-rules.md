# 产品语言写作规范

## 读者定位（先锚定读者，再动笔）
- 读者为资深研发 / 产品经理，具备领域基础常识。
- **禁止**解释行业通用概念、**禁止**铺垫背景意义、**禁止**科普式展开（如「随着业务的发展」「在数字化转型的背景下」）。
- 默认读者已理解业务上下文，直接输出核心信息。

## 核心原则
- 全篇使用产品语言，站在用户与业务视角描述"做什么"，不描述"怎么做"
- 禁止出现技术实现细节，技术细节属于技术方案设计范畴
- 所有业务规则必须明确、无歧义，避免模糊形容词
- 高信息密度：能用一句话说清的绝不写两句，能用表格/列表呈现的绝不写成长段落

## 文风负面清单（生成时主动规避，出现即删）
以下三类表述一经出现即视为冗余，直接删除或改写：

### 空泛形容词 / 程度副词（无量化即禁用）
显著、有效、极大地、全方位、一定程度上、较为、大幅、充分、良好、优秀、完善、高效

### 铺垫过渡句（直接删除）
众所周知、值得一提的是、综上所述、由此可见、不难发现、随着……的发展、在……的背景下

### 同义重复（合并为一句）
- 同一句话换句式反复说明
- 同一概念用多个近义词赘述（如「快速、高效、及时」连用）
- 前文已用表格 / 锚点表达的内容，后文再用段落复述一遍

## 冗余精简示例（啰嗦 → 精简）

| 啰嗦（反例） | 精简（正例） |
|---|---|
| 众所周知，随着业务的持续快速发展，企业对载体管理的需求日益增长，传统的线下管理方式已无法有效满足业务需要，亟需进行系统化改造 | 现有载体台账为线下 Excel 管理，月均登记错误 12 笔，无法满足审计要求 |
| 本功能可以显著提升审批效率，极大地改善用户体验，全方位优化业务流程 | 载体流转审批周期由 3 天缩短至 4 小时内 |
| 系统应快速、高效、及时地响应查询请求，确保用户获得良好的使用体验 | 单载体查询响应时间 ≤ 1 秒（P95） |

## 禁止出现的技术细节
以下内容严禁出现在 PRD 初稿中：
1. 代码层面：类名、方法名、函数名、变量名
2. 数据层面：数据库表名、字段名、主键外键、索引设计
3. 接口层面：接口路径、请求参数、返回字段、HTTP 方法
4. 技术选型：框架名称、组件名称、中间件选型
5. 实现方案：具体算法、技术架构、部署方式

## 正确产品语言示例
### 错误写法（技术细节）
- 用 React 实现表格的多列排序功能
- 调用 /api/order/create 接口创建订单
- 用户表新增 is_vip 字段标记会员状态

### 正确写法（产品语言）
- 支持用户对列表数据按多个维度进行排序，支持自定义保存排序规则
- 订单提交后，系统自动完成订单创建并同步至订单管理模块
- 支持标识会员用户身份，并在列表中进行区分展示

## 业务规则表述规范
1. 避免模糊表述：
   - ❌ 系统应在较短时间内响应
   - ✅ 系统响应时间应在 2 秒以内
2. 明确触发条件：
   - ❌ 系统在合适的时机同步数据
   - ✅ 审核通过后 5 分钟内，将数据同步至 ERP 系统
3. 统一术语：全文同一业务对象必须使用完全相同的术语表述

## 场景层引用规范
1. 涉及通用能力时，使用锚点引用格式：`详见 [能力名称](#{前缀小写}-cap-xxx)`（如 `详见 [资源管理](#uap-cap-001)`）
2. 禁止大段复制通用能力的完整描述
3. 存在差异时，引用后补充"差异说明"段落，仅描述不同点
4. 场景专属功能在场景下完整描述，不得放入通用能力层

## 锚点定义规范（保证文档内链接可跳转）
1. 每个通用能力/业务场景标题处，必须用显式 HTML 锚点定义跳转目标：
   - 通用能力：`<a id="{前缀小写}-cap-xxx"></a>`（xxx 为 3 位数字，如 `uap-cap-001`）
   - 业务场景：`<a id="{前缀小写}-scene-xxx"></a>`（如 `uap-scene-001`）
2. 锚点 ID 规则：统一**小写**、**ASCII 连字符 `-`**、数字序号；禁止使用非 ASCII 连字符（如 U+2011 `‑`）或中文标点，否则引用与目标不匹配导致链接无法跳转。
3. **编号前缀（命名空间）**：`{前缀小写}` 取本需求的「需求编号前缀」小写形式（大写前缀 `UAP` → `uap`；含连字符的前缀 `CRM-ORDER` → `crm-order`）。全文锚点必须使用同一前缀，禁止混用无前缀锚点（如 `cap-001`）或不同前缀。
4. 引用必须与目标 ID 完全一致：`[能力名称](#uap-cap-001)` 的 `#uap-cap-001` 必须精确对应某处 `<a id="uap-cap-001"></a>`。
5. 采用显式 `<a id>` 而非依赖标题自动生成的 slug，以兼容主流 markdown 渲染器（VS Code / GitHub / Typora 等）。
