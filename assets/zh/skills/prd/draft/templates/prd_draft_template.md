# PRD 初稿内容模板（draft 专用 · 初稿级）

> 用途：供 Phase2 逐章生成时对照。本模板是「方案大逻辑评审对齐」稿，**只写核心逻辑，不展开终稿细节**——完整权限矩阵、完整接口字段、完整数据模型、完整排期、埋点等留待 `refine` 终稿阶段。
> 配套方法论：复杂度分级裁剪、问题‑方案‑目标逻辑、架构图+流程图视觉语言、MoSCoW 优先级、风险前置、重点突出与无歧义语言、初稿边界检查。

---

## 0. 文档头部（合并阶段生成，置于首章之前）

- **文档类型**：PRD 初稿（工作稿，非终稿交付件）
- **基线来源**：{Baseline 标识}
- **澄清纪要**：{澄清纪要标识，若无标注「未提供」}
- **复杂度等级**：{简单 / 标准 / 复杂} → 决定内容深度（见下文裁剪规则）
- **重点保留率**：XX%
- **评审重点指引（必填）**：列出 2—5 条本次评审需重点确认的核心问题，引导评审者按「先业务价值 → 再方案大逻辑 → 最后功能细节」顺序阅读。

## 0.1 文档摘要（问题‑方案‑目标）

- **真实业务问题（问题先行）**：用证据链支撑（工单数据 / 运营数据 / 调研结论 / 往期经验），不用「提升体验」等空泛结论。
- **整体解决方案（方案后置）**：功能作为解决业务问题的手段，而非目标本身。
- **业务目标（目标闭环）**：SMART 可量化指标，与上方痛点一一对应（来自 Baseline「业务目标与验证指标」）。

## 一、需求背景（对应 01-需求背景.md）

- **问题先行**：真实业务问题 + 证据链。
- **方案后置**：整体解决思路概述。
- **目标闭环**：SMART 量化指标（直接承接 Baseline 业务目标与验证指标）。
- **本次范围（In）**：核心功能清单。
- **本次不包含（Out / 排除项清单）**：明确的不做事项，例如「本次迭代不支持跨境支付」「不涉及现有 ERP 订单模块改造」。排除项即 MoSCoW 的 WON'T HAVE 体现。

## 二、业务流程与时序（对应 02-业务流程与时序.md）

- **先图后文**（核心视觉语言）：
  1. 架构图（应用架构 / 模块划分 / 调用关系）
  2. 业务流程图（BPMN 或带判断节点的泳道图，覆盖主流程与主要分支）
  3. 状态机图（核心业务对象如订单/合同/结算单的生命周期与变更条件）
  4. 线框图（长链路多步操作的页面跳转，非高保真原型）
- **文字描述**：正常主流程 + 主要分支流程；不覆盖所有异常分支。
- **风险与应对（提纲级）**：按 **技术 / 业务 / 合规 / 依赖** 四类列风险点与应对策略，源自 Baseline「核心约束汇总」+ 澄清纪要「隐含假设与风险清单」。只写风险点与应对，不展开终稿细节。

## 三、需求详情（对应 03-需求详情-通用能力层.md / 03-需求详情-业务场景层.md）

- **优先级分级（MoSCoW）**：每个功能点标注 MUST / SHOULD / COULD / WON'T；按优先级排序（MUST 在前，WON'T 单独排除段）。
- **锚点引用**：场景层用 `[cap-xxx](#cap-xxx)` 引用通用能力，禁止大段复制通用能力原文，只写场景触发条件、流程、独有差异规则。
- **功能描述格式（用户故事 + 业务规则）**：
  - 用户故事：作为 `[角色]`，我想要 `[动作]`，以便 `[业务价值]`。
  - 业务规则：明确规则、判断条件、约束。**避免模糊主观表述、避免技术指令性表述、明确逻辑判断条件、统一术语**。

## 四、版本记录（04-版本记录.md）／五、更新记录（05-更新记录.md）

## 附：重点优化规范（初稿视觉，呼应自检 C）

- 核心结论：用「重点摘要区块（灰底）+ 加粗」突出。
- 重大风险 / 验收标准：高亮标注。
- 不同优先级功能点：用分隔线分开。
- 重点标注不过度，仅用于真正核心内容（整篇高亮 = 无重点）。

## 附：复杂度裁剪规则（呼应 Phase1 复杂度等级）

- **简单（L1-L2 级对应）**：仅覆盖背景、范围与排除项、核心功能 MUST 点、风险提纲；图表可精简为 1 张业务流程图。
- **标准（L3 级对应）**：覆盖背景、目标、范围、流程全图、需求详情（MoSCoW）、风险提纲、待决；图表齐备。
- **复杂（L4 级对应）**：在标准基础上，强化架构图与状态机、补充依赖与约束，但不突破「初稿只写大逻辑」边界。
