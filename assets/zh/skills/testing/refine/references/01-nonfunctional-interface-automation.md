# 非功能 / 接口 / 自动化用例判据（testing 族）

> 归属：`polaris{{SKN_SPR}}testing{{SKN_SPR}}refine`。功能用例的判据不在这里——它在 `polaris{{SKN_SPR}}testing{{SKN_SPR}}draft` 的 `references/01-case-design-criteria.md`。
> 本文件只覆盖**功能用例之外的三类增量拓展**：非功能（性能 / 安全）、接口、自动化转化。

---

## 一、非功能用例

### 1.1 性能测试用例

**输入**：PRD 非功能需求中的性能指标（响应时间 / TPS / 并发量 / 数据量）。**指标缺失时记入待确认清单并停止该项，禁止编造阈值**。

| 场景 | 设计要点 | 判定依据 |
|---|---|---|
| **基准场景** | 基于 L1 主流程设计单用户基准用例，测核心接口/页面的响应时间与吞吐基线 | 单用户指标阈值 |
| **并发场景** | 针对核心业务节点设计多用户并发用例，验证并发处理能力与数据一致性 | 并发量 + 一致性 |
| **压力场景** | 超负载压力用例，验证系统极限承载与错误率拐点 | 极限指标 + 错误率 |
| **稳定性场景** | 长时间稳定运行用例，验证内存/连接/性能不退化 | 持续时长 + 退化阈值 |

**硬规则**：每条性能用例**必须带指标阈值**（数值 + 单位），阈值是结果判定的唯一依据；无阈值的性能用例**不得入库**。

### 1.2 安全测试用例

**设计立场**：把安全验证点**嵌进功能流程**，而不是脱离业务做纯技术扫描。

| 维度 | 覆盖点 |
|---|---|
| **基础安全** | 认证授权、数据权限、输入校验（防注入 / XSS）、敏感数据脱敏 |
| **业务安全** | 越权访问、业务逻辑漏洞、接口重放、数据篡改 |

**硬规则**：

- 安全清单的**唯一源**是 `polaris{{SKN_SPR}}maintance{{SKN_SPR}}codereview` 的 `references/security-checklist.md`——本族**只给指针，不重写、不复制**清单内容；
- 按功能模块梳理风险点，安全用例与对应功能用例**对应存放**；
- 无法在功能流程内验证的项（如需专业渗透工具）标记「超出本族范围」，不计入覆盖。

## 二、接口测试用例

基于接口清单（如 ApiFox 导出）按「单接口 → 场景串」渐进编写。**接口清单属可选输入**：缺失时记 `No-Input` 并声明「本版不做接口用例」，不阻断。

### 2.1 单接口用例

| 覆盖项 | 说明 |
|---|---|
| 正向请求 | 合法入参、标准响应 |
| 参数异常 | 非法参数、必填缺失、类型错误 |
| 边界值 | 数值/长度/集合的临界与越界 |
| 权限校验 | 无凭证 / 越权 / 令牌过期 |

**鉴权项细目**（覆盖项「权限校验」的展开，逐项至少 1 条）：

| 组 | 项 |
|---|---|
| 认证 | 有效 Token / Token 过期 / Token 为空 / Token 伪造或损坏 |
| 权限 | 有权限访问 / 无权限访问 / 跨角色访问（A 角色访问 B 角色资源） |

### 2.2 业务场景用例（接口串）

按 **L1–L2 业务流程**串联多个接口，模拟真实业务链路的接口流转与数据传递。

### 2.3 设计原则（与自动化工具的契约）

- **入参可配置**：环境、账号、业务数据参数化，不硬编码
- **断言明确可量化（四层，前三层必备）**：① HTTP 状态码 → ② **业务响应码** → ③ 关键返回字段与结构 → ④ **数据库断言**（落库状态，对齐扩展项 E6）；禁止「返回成功即可」
- **测试数据可自动清理**：用例执行后不残留脏数据

> 断言只到**概念层**（要断言哪几层）。具体断言库、断言代码属**执行实现**，归 `polaris{{SKN_SPR}}coding{{SKN_SPR}}verify`，本族不写。

> **与执行口径的边界**：接口用例在 `polaris{{SKN_SPR}}coding{{SKN_SPR}}verify` 中对应 **`contract` 槽**。本族只**产出**接口用例（对齐该槽的语义与粒度），**不定义**执行方式、探测规则与判定逻辑——执行口径的唯一源在 verify。

## 三、自动化用例转化

### 3.1 转化顺序（渐进，禁止一次全转）

| 批次 | 转化对象 | 目的 |
|---|---|---|
| 第 1 批 | **L1 主流程用例** | 支撑版本快速冒烟验证 |
| 第 2 批 | **L2 核心功能用例** | 覆盖全量回归的核心业务场景 |
| 第 3 批 | 高频回归的 **L3 异常用例** | 降低手工重复回归成本 |

原则：**先核心后边缘、先正向后反向**。

### 3.2 转化要点

- **保留业务语义**：转化后仍能读懂「在验证什么业务行为」，不得退化为纯元素操作流水
- **补齐自动化要素**：元素定位、数据驱动、断言逻辑
- **结果自动校验**：断言可自动判定成败，不依赖人工看图
- **可重复执行**：数据自备自清，不依赖执行顺序

### 3.3 产物

- 自动化用例清单（哪些用例已转、属第几批、脚本路径）
- 自动化测试报告模板（结构由项目实际框架决定；本族只给**结构要求**，不绑定具体框架）

> 自动化脚本的**执行**同样归 `polaris{{SKN_SPR}}coding{{SKN_SPR}}verify`（五槽探测中的 `unit` / `contract` / `integration` / `smoke`）；本族只产出资产。
