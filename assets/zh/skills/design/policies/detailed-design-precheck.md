# 专项设计预检 — detailed-design 完成后的专项范围

## 核心原则

- **时机**：仅在 `openspec/changes/<change_id>/detailed-design.md` **已落盘**之后执行；**不是**判断要不要写详细设计
- **目的**：对照 proposal / 高层 `design.md` / 已写的 `detailed-design.md`，判断是否还需**补充**专项 `<slug>-design.md`，以及补充哪些、范围多大
- 预检结论是**建议**；判定需补充后，须在 §5 把各专项的**推荐范围（范围内/范围外）**呈现给用户选择。AI 不得代决「一律不补」或「一律全开」
- 专项是对 `detailed-design.md` 的**拆分加深**，不是重开一套需求；不得借专项扩大 propose 已锁定的目标/非目标
- 专项命名与落盘：变更根目录扁平 `<slug>-design.md`；禁止文件名 `design.md`；禁止写入 `design/` 或任何子目录

---

## 1. 输入清单（执行前必须齐备）

| 输入 | 必读 | 用途 |
|------|------|------|
| `openspec/changes/<change_id>/detailed-design.md` | **是（前置）** | 已写深化内容；判断哪些面已够用、哪些仍空洞 |
| `openspec/changes/<change_id>/proposal.md` | 是 | 范围、非目标、冲击面 |
| `openspec/changes/<change_id>/design.md` | 是 | 高层模块/API/存储提纲，对照缺口 |
| `openspec/changes/<change_id>/specs/*/spec.md` | 建议 | 验收是否依赖未单独成文的契约/数据形状 |
| `openspec/changes/<change_id>/intention.md` | 若有 | 选型与下游约束 |
| 已有 `openspec/changes/<change_id>/*-design.md` | 若有 | 避免重复建议；可建议修订而非新建 |

`detailed-design.md` 不存在 → **阻断本预检**，先完成 SKILL Step 3.1。

---

## 2. 可不补充专项的判定门

仅当以下**全部**满足时，可建议「无需专项，`detailed-design.md` 已覆盖」——仍须经用户确认：

| # | 条件 |
|---|------|
| N1 | `detailed-design.md` 对实现方案、风险、测试、边界已写清，无大段「见专项 / TBD / 后续补充」 |
| N2 | 无独立成文必要的领域模型关系网、表级 ER、仓储边界或 API 请求/响应/错误码细节 |
| N3 | proposal / 高层 design 中的 API 清单、存储要点、模块划分已在 `detailed-design.md` 内展开到可指导 plan/build |
| N4 | 不存在「详细设计点到了某面，但深度不够、继续塞进总文档会过载」的章节 |

**任一不满足 → 至少建议一类专项**（见 §3）；不得仅用 N1 口头带过。

---

## 3. 专项推荐矩阵

对照 **proposal + 高层 design + detailed-design** 勾选。**只推荐有证据且 detailed-design 尚未写透的类别**；已在总文档写透的不展示。

| 专项文件 | 模板（相对本 skill） | 推荐条件 |
|----------|----------------------|----------|
| `domain-model-design.md` | `./templates/domain-tech-template.md` | 新/改聚合根或实体关系；状态机；限界上下文；detailed-design 仅列模块名未给模型表/关系图 |
| `data-model-design.md` | `./templates/datamodel-tech-template.md` | 新表/改表/索引/迁移；detailed-design 未给 ER 或表结构 |
| `repository-design.md` | `./templates/storage-tech-template.md` | 仓储抽象、读写路径、缓存与一致性；detailed-design 未划仓储边界 |
| `restful-api-design.md` | `./templates/restfulapi-tech-template.md` | 新增或破坏性 API 契约；design 有清单但缺请求/响应/错误码；联调依赖契约 |

「其他」：上述四类盖不住、且文档明确点名某技术面（鉴权协议、消息拓扑、批处理编排等）→ 用户确认英文 kebab `slug` → `<slug>-design.md`。

### 3.1 推荐强度

- **强烈建议**：缺独立文档则 plan/build 高概率返工（契约、表结构、聚合边界）
- **建议**：总文档已有提纲，拆出专项更利于评审与联调
- **可选**：信号弱；可继续留在 `detailed-design.md` 一小节

### 3.2 每项须界定范围

对建议的每一专项，必须写清：

- **范围内**：本专项要写到的章节/对象（对照模板）
- **范围外**：明确不写、留给 `detailed-design.md` 或其它专项的内容
- **与 detailed-design 的关系**：补充 / 展开哪几节，禁止简单复制粘贴总文档

## 4. 预检输出格式（必须）

先完成 §2–§3 判定，再输出下列结构（可微调措辞，字段不可缺）。**有推荐项时，§4 的清单必须原样带入 §5 供选择，不得只给抽象 A/B/C。**

```markdown
专项设计补充预检

**变更**：`<change_id>`
**前置**：detailed-design.md 已落盘

**结论**：
- 专项：<无需补充 | 建议补充下列项>

**依据**（引用 detailed-design / proposal / design，1–4 条）：
  · <依据 1>
  · <依据 2>

**建议专项清单**（将作为 §5 选项来源）：
| # | 专项文件 | 强度 | 范围内 | 范围外 | 模板 |
|---|----------|------|--------|--------|------|
| 1 | <slug>-design.md | … | … | … | ./templates/… |

**若不补专项的风险**（存在「强烈建议/建议」项时必写）：
  · <风险 1>
```

无推荐项时，「建议专项清单」写「无」，结论为「无需补充」，仍进入 §5 做一次性确认。

然后进入 §5。

---

## 5. 用户决策点（阻塞）— 呈现推荐范围供选择

按 `./policies/decision-point.md` 暂停。**必须先完整展示 §4 输出**，再发起选择。

### 5.1 结论为「无需补充」时

单选：

| 选项 | 含义 | 后续 |
|------|------|------|
| A. 确认无需专项 | 仅保留 `detailed-design.md` | 跳过专项落盘，进压缩/评审 |
| B. 仍要补充 | 用户点名专项或改范围 | 回到 §3 补清单后重跑 §4–§5 |

### 5.2 结论为「建议补充」时（主路径）

将 §4「建议专项清单」**逐条**呈现为可选范围（优先多选；平台无多选则编号勾选后一次确认）。每一选项必须带上预检给出的**范围内 / 范围外**，不得只报文件名。

展示模板（字段来自 §4 表格，禁止省略范围）：

```text
请选择要补充的专项设计（可多选；推荐项已按强度标出）：

[ ] 1. <专项文件>　（<强度>）
      范围内：<…>
      范围外：<…>
      模板：./templates/…

[ ] 2. …

[ ] N. 不补充任何专项（仅保留 detailed-design.md）
      风险：<引用 §4 若不补的风险；无强烈建议项时可写「无额外风险」>

[ ] N+1. 自定义：其他 slug / 调整某项范围内外
      （选此项须在回复中写明文件名与范围内外）
```

规则：

1. **默认勾选**：所有「强烈建议」+「建议」项预勾；「可选」默认不勾，但仍列出供用户加选
2. **用户可改**：取消预勾、加选可选项、或只选子集——以用户最终勾选为准
3. **选「不补充任何专项」**：不得与其它专项勾选同时生效；若存在「强烈建议」项，须在确认语中复述风险后再继续
4. **选「自定义」**：用户补全后，回显最终清单（含每项范围内外）再确认一次，然后落盘
5. AI **不得**代用户勾选或把「全开/全关」当成默认提交

确认后的最终清单（文件名 + 范围内 + 范围外）写入会话，再按清单落盘；不得再另开与预检无关的专项菜单。

**禁止**：

- 在 `detailed-design.md` 落盘前跑本预检
- 未展示 §4 清单与范围内外就让用户选择
- §5 只给「按建议 / 不补充 / 自定义」三句空选项、不展开各专项范围
- 确认前创建或覆盖 `*-design.md`
