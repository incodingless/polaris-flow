# bugfix 交付报告模板

> **使用范围**：仅 `polaris{{SKN_SPR}}debug{{SKN_SPR}}closeout` 技能。
> **落盘路径**：`.polaris/tasks/<issue_id>/reviews/bugfix-report.md`。本通道**不使用 openspec**；收尾时复制到 `docs/troubleshooting/<issue_id>/bugfix-report.md`。
> **原则**：报告的每一节都必须有对应证据；无证据的结论不得写入。

## 模板骨架

```markdown
# <issue_id> — 测试缺陷修复交付报告

## 1. 结论

- **现象**：<一句话>
- **根因**：<引用 reviews/rca-report.md，不重述>
- **修复**：<一句话>
- **状态**：<已修复 / 部分修复（残留现象见第 7 节）>

## 2. 输入四要素

| 项 | 内容 |
|----|------|
| 复现步骤 | 1. … 2. … |
| 实际结果 | <原始报错 / 截图路径> |
| 预期结果 | … |
| 环境版本 | <分支 / commit / 服务版本 / 配置 / 数据状态> |

## 3. 复现

- **复现产物**：<单测 / 脚本 / 请求，文件路径>
- **原始输出**：<原样粘贴，不摘要>
- **稳定性**：连续 <N> 次运行，<N> 次同结果

## 4. 根因与证据链（引用 rca-report.md）

- 根因结论与九节详见 `reviews/rca-report.md`；本报告只留指针，不重述

## 5. 方案与影响面

- **选定方案**：<一句话>
- **未选方案与理由**：<方案 B / C 及为何不选；无分叉时写「无分叉，唯一路径」>
- **改动点清单**：
  | 文件 | 位置 | 改什么 |
  |------|------|--------|
- **影响面**：上游调用方 / 下游依赖 / 关联模块 / 对外接口
- **回归范围**：<必须复跑的既有用例与场景>

## 6. 验证结果

| 验证项 | 命令 | 结果 | 证据 |
|--------|------|------|------|
| 原复现用例 | `<cmd>` | 通过 | <输出摘要 / 退出码> |
| 新增边界用例（≥2） | `<cmd>` | 通过 | |
| 回归范围用例 | `<cmd>` | 通过 | |
| 静态检查 | `<cmd>` | 通过 | <既有告警 N 条，本次引入 0 条> |
| diff 范围校验 | `git diff --stat` | 无夹带 | |

## 7. 未覆盖项与残留现象

- **未执行 / 未验证项**：<项 + 原因 + 影响>（B 档能力降级必须写在此处）
- **残留现象**：<根因未能解释的现象 + 归因未知声明；无则写「无」>

> 禁止用「无性能退化」「环境正常」等无证据表述替代本节。

## 8. 交付物清单（出口门禁自检）

| # | 交付物 | 状态 |
|---|--------|------|
| 1 | `.polaris/tasks/<issue_id>/diagnose-brief.md` | ✅ / ❌ |
| 2 | `.polaris/tasks/<issue_id>/reviews/rca-report.md` | ✅ / ❌ |
| 3 | `.polaris/tasks/<issue_id>/tasks.md`（tasks-lint 通过） | ✅ / ❌ |
| 4 | 修复代码（diff 无夹带） | ✅ / ❌ |
| 5 | 新增用例（覆盖故障路径 + 边界 ≥2 条） | ✅ / ❌ |
| 6 | 本报告 | ✅ / ❌ |
| 7 | 标准化提交信息 | ✅ / ❌ |
| 8 | `.polaris/metrics/<timestamp>-metrics.json` | ✅ / ❌ |

## 9. 评审要点（供 CR 使用）

- **根因**：<一段话>
- **改动范围**：<N 个文件 / M 行，全部落在改动点清单内>
- **风险点**：<可能受影响的相邻路径 / 未覆盖场景>
- **测试覆盖**：<新增用例覆盖了哪些路径；未覆盖哪些>
- **未覆盖项**：<见第 7 节>

## 10. 归档

- 归档目录：`docs/troubleshooting/<issue_id>/`
- 归档文件：`diagnose-brief.md` / `rca-report.md` / `tasks.md` / `bugfix-report.md`
- 同类索引：`docs/troubleshooting/INDEX.md` 已追加本 issue 一行（模块 / 异常类型 / 根因 / 修复）
- 回读校验：<4 个文件 + `INDEX.md` 均存在且非空>
```

## 强制规则

1. **每一节都要有证据**——结论、命令、输出三者齐全，缺证据的结论不得写入
2. **第 7 节不可省略**——无未覆盖项也要显式写「无」
3. **第 8 节是出口门禁**——④ 修复代码、⑤ 新增用例、⑥ 本报告三项缺任一项，不得输出最终结果
4. **不得美化结论**——部分修复就写「部分修复」，并列出残留现象
5. **第 10 节需在 `closeout` 归档后被回读校验 5 项**，校验不通过不得宣告收尾完成
6. **本通道不代为提交**——只产出提交信息文本；`git add` / `commit` 仅在用户明确选择后执行，`push` / 合并 / PR 一律不代为执行
