# debug 族 · 场景分流

本族两条通道按**场景**并列：`bugfix`＝测试缺陷修复，`hotfix`＝生产故障修复。**不按紧急度分流**——紧急不等于简单；根因未定的线上事故必须走生产通道，根因已定位的测试缺陷也照样走完测试通道。

## 生产信号（命中任一即停止测试通道，转 `hotfix`）

1. 环境是生产 / 线上 / 灰度真实流量
2. 已影响真实用户或真实数据
3. 来自线上告警、监控、客服工单
4. 用户表述中出现「线上」「生产」「用户反馈」「赶紧上线」

## 不适用本族的情形 → 转 coding 族

| 情形 | 应走的通道 |
|------|-----------|
| 「根因」其实是需求写错了、预期行为变了 | `coding/normal` 或 `coding/tweak` |
| 改动跨 3+ 模块 / 需 schema 或数据迁移 / 对外 API breaking | `coding/normal` |
| 不改变外部行为的结构调整 / 性能优化（性能问题不等于缺陷） | M03 重构 |
| 无法复现、也无任何证据 | 先补日志 / 指标观测，重新提单 |
| 需要产出 OpenSpec 规格与四件套 | `coding/normal` |

## bugfix vs hotfix 边界

| 维度 | bugfix（测试缺陷） | hotfix（生产故障） |
|------|-------------------|-------------------|
| 场景 | 测试 / 提测 / 联调发现 | 生产 / 线上 / 灰度真实流量 |
| 根因 | 未定位，本通道定位 | 通常未定位，本通道在**现场保全后**定位 |
| 阶段装配 | `triage→diagnose→prescribe(可折叠)→patch→closeout`（**不装 `prove`**） | 全六段 + `prove`（`prescribe` 不可折叠） |
| 人确认点 | 根因（必选）+ 方案（仅分叉时） | 根因 + 方案 + 发布确认 |
| 运行态 | `.polaris/tasks/<issue_id>/`，全程不使用 openspec | 同左 |

用户只说「修 bug」不分场景时，按信号判定；信号不足**必须询问**，不得默认某一通道。

## 人在环节点（生产通道专属，不建技能）

生产通道在技能阶段之外有三个**人在环节点**，技能只出 `templates/` 下的可执行指引，**不执行**：

1. **现场保全**（`triage` 之前）：留什么 / 时间窗 / 从哪取 / 为什么。
2. **止血**（`diagnose` 之后任意时点，支路）：回滚 / 关开关 / 限流 / 降级 / 数据冻结的选项卡 + 恢复判定口径。
3. **发布 / 灰度 / 回滚**（`closeout` 之后）：发布前置检查、回滚触发条件、灰度阶段与放量比例、观测指标与阈值。
