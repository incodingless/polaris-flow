# verification 模板（一份两节）

> 落盘：`.polaris/tasks/<issue_id>/verification.md`（需先 `mkdir -p` 所在目录）。
> 「自验」节由 `patch` 写，「独立验证」节由 `prove` 回填（含人回填结果）。命令 + 原始输出 + 结论，三件套，缺证据不写。

```markdown
# <issue_id> — 验证记录

## 自验（patch 写 · 技能自证）

| 验证项 | 命令 | 结果 | 证据 |
|--------|------|------|------|
| 原复现用例 | `<cmd>` | 通过 | <输出摘要 / 退出码> |
| 新增边界用例（≥2） | `<cmd>` | 通过 | |
| 回归范围用例 | `<cmd>` | 通过 | |
| 静态检查 | `<cmd>` | 通过 | <既有告警 N 条，本次引入 0 条> |
| diff 范围校验 | `git diff --stat` | 无夹带 | |
| 数据脚本幂等自审 / 埋点 / 开关（仅生产通道） | `<cmd>` | 通过 | |

## 独立验证（prove 写 · 人回填 + 技能判定 · 仅生产通道）

| 维度 | 执行人 / 环境 | 结果 | 证据 |
|------|--------------|------|------|
| 功能回归 | | | |
| 数据兼容（含脚本重复执行） | | | |
| 性能基准（无退化） | | | |
| 边界与异常 | | | |
| 回滚演练（业务与数据可恢复） | | | |

> 独立验证多为 B/C 档：无法在技能可及环境执行的项目，标注「未验证 + 原因」，不得写成「无性能退化」等无证据表述。
```
