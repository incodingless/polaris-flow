# diagnose-brief 模板（过程档案）

> 落盘：`.polaris/tasks/<issue_id>/diagnose-brief.md`。
> **过程档案**：原始证据原样、调研路径、中间结论与被推翻的假设；**只追加、不美化**，允许自相矛盾、允许留废稿。分段回填，每段只写自己负责的节（见下）。

```markdown
# <issue_id> - 缺陷诊断档案

## 缺陷信息（diagnose 写）
- 来源：<Jira 单号 / 用例编号 / 测试同学 / 提测回归 / 线上告警>
- 问题单：<Jira 单号 + 读取方式：Jira MCP 读取 / 手动补充 / 无单号>
- 严重程度：<阻塞 / 严重 / 一般 / 故障等级>
- 场景判定：<测试 / 生产>（channel：<bugfix / hotfix>）
- 历史同类：<issue_id / 无>（diagnose 索引检索结果）

## 输入四要素（diagnose 写，测试通道）
- 复现步骤：1. ... 2. ...
- 实际结果：<原始报错 / 截图路径>
- 预期结果：...
- 环境版本：<分支 / commit / 服务版本 / 配置>

## 故障信息三对齐（diagnose 写，生产通道）
- 时间线：<异常起始 / 扩散 / 峰值点，显式对齐时区>
- 影响面：<受影响用户量 / 功能范围 / 损失等级>
- 变更清单：<故障窗口内的代码发布 / 配置 / 依赖 / 数据变更>

## 现场保全（diagnose 写，生产通道）
- 保全清单：<引用 preservation-checklist.md 产物>
- 回填结果：<人执行后回填：导出路径 / 时间戳；未保全项 + 原因>

## 证据提取（diagnose 写）
| 项 | 值 |
|----|----|
| 异常类型 | |
| 报错位置 | <path:line> |
| 所属模块 | |
| 触发请求 | |

## 复现（diagnose 写；生产通道可选）
- 复现产物：<单测 / 脚本 / 请求，路径>
- 执行输出：<原始输出，原样>
- 稳定性：<连续 N 次同结果 / 未复现 + 原因>

## 止血（人在环回填，生产通道）
- 选的手段：<回滚 / 关开关 / 限流 / 降级 / 数据冻结 / 停止订正>
- 执行结果：<人回填>
- 恢复指标：<截图 / 指标回填>

## 根因（diagnose 写）
- 文件：`<path>:<line>`
- 函数：`<func>`
- 直接原因 / 根本原因：<二者分开写>
- 证据链：<栈溯源路径 + 变更关联 + 排除记录>
- 解释范围：<能解释全部现象 / 残留现象：...>

## 修复方向（diagnose 写）
- 改：<path:line> <改什么>
- 加：<新增什么>
- 删：<删除什么>
- 影响面：<上游调用方 / 下游依赖 / 关联模块 / 对外接口>
- 回归范围：<必须复跑的既有用例 / 场景>
```
