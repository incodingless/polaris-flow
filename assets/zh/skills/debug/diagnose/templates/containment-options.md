# 止血选项卡（生产通道 · 人在环）

> **使用范围**：仅 `polaris{{SKN_SPR}}debug{{SKN_SPR}}hotfix` 通道。**支路**，可在 `diagnose` 之后任意时点插入。
> **定位**：业务还在受损时，先给止血选项，再谈根因。技能产出**选项卡**（多手段 + 每项代价），由人挑选并执行。
> **执行方**：**只由人执行**。技能不执行、不声称已执行（C 档）。

## 触发规则（什么时候必须出选项卡）

1. **影响面已经开始收割**（真实用户受损 / 资金或数据在写）且已有变更清单 → 在给出根因结论**之前**先出止血选项卡，不许「查完再说」。
2. **根因已明确但修复需要发布窗口** → 止血与修复**并行**推进，禁止串行等待。
3. **无止血手段**（无开关、无回滚点、数据已污染且无订正能力）→ 在交付物里高亮为**最高风险项**，要求人显式回答「是否接受带伤运行」，技能**不得**自行判断可以接受。

## 选项卡结构（每项一行，不能只给一条命令）

技能无法复核生产当前状态，单条命令式建议可能造成二次伤害——必须给出**多手段选项卡**，每项含：

| 字段 | 说明 |
|------|------|
| 手段 | 候选止血动作 |
| 适用前提 | 什么条件下可选这项 |
| 操作步骤草案 | 可执行的步骤（草案，需人按现场确认） |
| 前置校验 | 执行前必须确认的条件 |
| 副作用 | 可能的代价 |
| 失败下一步 | 该手段无效时怎么办 |

## 候选手段集（至少覆盖以下，按现场增删）

| 手段 | 适用前提 | 副作用 | 失败下一步 |
|------|---------|--------|-----------|
| 回滚最近发布 | 异常与最近一次发布强相关、有回滚点 | 回滚期间短暂中断 | 回滚失败则关开关 / 限流 |
| 关闭特性开关 | 该功能有开关 | 该功能不可用 | 无开关则回滚 |
| 限流降级 | 有网关 / 降级组件 | 部分请求被拒 | 降级无效则回滚 |
| 数据冻结 | 数据仍在被污染写入 | 相关写操作暂停 | 冻结后评估数据订正 |
| 停止数据订正 | 已有订正脚本在跑且可能加重 | 数据停留在当前状态 | 评估订正脚本回滚 |

> 每个手段的「操作步骤草案 / 前置校验」由技能结合具体缺陷补写；上表给的是骨架，**不得**只复制骨架交差。

## 恢复判定口径

止血**生效**的判定标准（技能提供口径，由人确认结果）：
- **业务指标恢复**：错误率 / 延迟 / 可用性回到故障前基线；
- **影响面停止扩散**：新增受损用户 / 数据量不再增长。

**技能不自行判定「业务已恢复」**——由人确认执行结果后回填，技能据回填结果继续或调整。

## 回填

人执行止血后，把「选的手段 / 执行结果 / 恢复指标截图」回填到 `diagnose-brief.md` 的「止血」段。
