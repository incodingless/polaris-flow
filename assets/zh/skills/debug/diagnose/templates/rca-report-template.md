# rca-report 模板（根因分析报告 · 成品）

> 落盘：`.polaris/tasks/<issue_id>/reviews/rca-report.md`（需先 `mkdir -p ".polaris/tasks/<issue_id>/reviews"`）。
> **成品报告**：给人确认根因、给 `prescribe` 当输入、随交付归档。一句话一个结论，无证据不写；**每项结论都必须能在 `diagnose-brief.md` 里找到对应证据（引用节名）**。九节固定结构：

```markdown
# <issue_id> — 根因分析报告（RCA）

## 1. 摘要与影响面
- 现象：<一句话>
- 影响范围：<模块 / 功能 / 波及面>

## 2. 时间线
- <生产必填：异常起始 / 扩散 / 峰值 / 恢复，显式对齐时区；测试通道写「不适用」>

## 3. 根因
- 直接原因：`<path:line>` — <一句话>
- 根本原因：<逻辑错误 / 设计缺陷 / 约束缺失，与直接原因分开写>

## 4. 证据链
- 栈溯源：<报错点 → … → 最早引入异常的节点>
- 变更关联：<git log / git blame 定位到的变更及其作用机制>
- 日志 / 指标引用：<指向 diagnose-brief.md 的节名>

## 5. 排除记录
| 替代假设 | 排除依据 |
|---------|---------|
| <假设一> | <证据> |

## 6. 解释范围
- 覆盖现象：<列出已解释的全部现象>
- 残留现象：<未解释的显式列出 + 归因未知声明；无则写「无」>

## 7. 发现路径（为何没被更早拦住）
- <用例没覆盖？参数校验缺失？监控未告警？环境差异？——直接产出「该补哪条用例」>

## 8. 结论置信度与未决项
- 置信度：<高 / 中 / 低> — <依据>
- 未决项：<建议补的观测手段 / 待确认项>

## 9. 改进项（不在本次范围，只登记不执行）
- <补用例 / 补校验 / 补监控 / 补文档；不进入本次改动，归档后供后续排期>
```
