# debug 族 · 能力分档（全流程通用）

本族每一步动作都必须能落到下表某一档。**禁止**把 B / C 档写成「自动完成」。

| 档 | 能力 | 落地要求 |
|----|------|---------|
| **A · 工具内原生可做** | 报错栈 / 日志文本解析、`git log` / `git blame` 变更关联、调用链阅读、最小复现脚本与单测生成、执行测试、静态检查、`git diff` 范围校验、生成交付文档、收尾归档 | 写成强制步骤，无需额外条件 |
| **B · 需环境接入** | 测试环境 / CI 执行、类生产或预发布验证、性能基准对比、日志平台聚合与 TraceId 关联、缺陷单系统读取 | 必须先声明依赖；不可用时按下表降级，并在交付报告「未覆盖项」标注 |
| **C · 只能由人提供或执行** | 生产 APM 指标曲线、现场保全执行、止血执行（回滚 / 关开关 / 限流 / 降级 / 数据冻结）、数据订正脚本实际执行、发布 / 灰度 / 回滚执行、告警平台与工单系统拉取 | 写成「须由用户提供输入 / 由用户执行」，**禁止**声称自动完成 |

## B 档降级路径（不可用时照此执行，不得跳过）

| 能力 | 降级方式 |
|------|---------|
| 测试环境 / CI 执行 | 在本地可执行范围内跑；无法执行则在交付报告标注「未在目标环境验证」并说明原因 |
| 类生产 / 预发布验证 | 标注「未在类生产环境验证」，并把五维验证中无法执行的项目写入「未覆盖项」 |
| 性能基准对比 | 不做性能结论；标注「性能未验证」，不得写成「无性能退化」 |
| 日志平台聚合 | 请用户粘贴原始日志，本族做结构化提取；提取不到则标注缺失字段 |
| 缺陷单系统读取（Jira MCP） | `diagnose` 的问题单接入步主动尝试调用 Jira MCP 读取问题单；未接 MCP 或读取失败 → 要求用户手动补充问题单内容；`issue_id` 用 Jira 单号（有单号时，不 LLM 推荐）或 kebab-case 命名（无单号时） |

## 生产通道的档位分布（相对测试通道）

生产通道的 **C 档远多于测试通道**：现场保全、止血、发布、灰度、回滚、生产数据订正全部是 C 档。技能侧只产出「可执行指引 + 判定口径」，执行与结果回填由人完成。门禁判定依据据此分三类：**技能自证**（A 档可复核）、**人确认**（对结论做判断）、**人回填 + 技能判定**（`patch` 的独立验证步用它）。
