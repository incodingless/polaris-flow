# 技能内「注释 / 解说 / 铺垫」盘点

> 扫描对象：`zh/skills/generate-prototype/`（27 个文件，约 10600 行）
> 扫描方式：ripgrep 标记词（本章/本节/本文件/继承/吸收/来源/历史/例如/值得…）+ 逐文件结构统计（标题 / 表格 / 引用块 / 注释行）
> 口径：**只找"不承担判据与指令职能"的文字**——即读完之后不改变任何动作的那部分。

## 7. G 类 · 契约型注释（**不可当"注释"清理**）

| 标记 | 作用 |
|---|---|
| `/* @TOKENS:BEGIN / END */` | scaffold 定位 Token 区 |
| `<!-- @ICONS:BEGIN / END -->` | 图标 sprite 区 |
| `<!-- @NAV:BEGIN / END -->` | 导航区 |
| `<!-- @PAGES:BEGIN / END -->` | 页面容器区 |
| `<!-- TODO: 页面主体 —— … -->` + `.page-desc` 占位文案 | 脚手架占位，提示"删除前不要交付" |
| `<pre id="__pvResult">` | verify 探针的渲染锚点 |

这些是**机器读取的接口**。清理注释时若把它们一起删掉，`scaffold` / `verify` 会直接失效——这是本盘点里唯一的"删了会坏事"类别。

## 8. 顺带查出的 4 处真缺陷（不是风格问题）

### 缺陷 1 · 章标题过时且名不符实
`references/03` 第 1 行：`# 6. 标准流程：8 个阶段`

- 工作流已于 2026-09-11 由 8 阶段扩为 **9 阶段**（`SKILL.md §四`），此标题未跟上；
- 且该节实际**只有阶段 1–5**（阶段 6 在 `ref04 §11`、阶段 7 在 `ref04 §12`、阶段 8 在 `ref05 §14`、阶段 9 只在 `SKILL.md §四`）——"标准流程：8 个阶段"作为标题本来就不准。

### 缺陷 2 · `SKILL.md §九` 的 ref07 内容清单里有一项不存在
该行列出 ref07 含「…最终判断标准、**版本记录**、核心公式」，但 ref07 实际到 **§37 核心公式**结束，**没有"版本记录"这一章**（§36 是最终判断标准、§37 是核心公式）。按该清单去找会落空。

### 缺陷 3 · 7 处「继承 / 吸收」指向技能内不存在的文档
`ref05` §14（"本章吸收现有《敏捷开发 Web 端界面规范文档》的方法与判据"）、§16、§17、§18、§19、§23，以及 `ref03` §10.2，共 **7 处**用「继承现有规范 / 继承 / 继承原规范」引出规则。

那份《敏捷开发 Web 端界面规范文档》**不在技能里**，读者无法追溯。这类"出处铺垫"读起来像有依据，实际不可验证——而且删掉"继承："二字，后面的规则一条不少。

### 缺陷 4 · `ref01` §1 的能力条目与边界规则冲突
- `ref01` §1 第 6 条：「如何**控制页面数量和一期范围**」；
- `ref07 §31.2`：「本技能默认不负责替产品经理决定：**页面数量上限/下限**、**项目范围取舍**…」。

两者语义相反。且 §1「能解决什么问题」11 条与 09-12 判定删除的 `SKILL.md §二`(1)–(8) 属同一层内容——当时没一并处理，是因为这份清单在 ref01。
