# Phase 0b — 复杂度判定

Phase 0 三项清单完成后**立即**执行。

## 判定信号

| 信号 | simple | standard | complex |
|------|--------|----------|---------|
| 模糊点 | 0（或 1 trivial 可自解） | 1–3 | 4+ 或架构级 |
| 范围 | 单文件/单模块 | 2–3 模块 | 多子系统/新 capability |
| 方案分叉 | 代码库唯一路径 | 2 种可行 | 3+ 或 BREAKING |
| 风险 | 低、易回滚 | 中 | 高（安全/数据/兼容） |

## 四档

- **simple** — 调研覆盖意图，模糊点为空，实现路径唯一 → 快速路径
- **standard** — 少量模糊点或有限方案选择
- **complex** — 多模糊点、架构决策、跨系统
- **needs_split** — 单 brainstorm 无法覆盖 → **STOP**，协助拆分后从 Phase 0 重入首项

## 输出

```markdown
## 复杂度判定
- 级别：simple | standard | complex
- 依据：[2–4 条调研证据]
- 计划路径：快速 | 标准 | 完整
- 预计澄清：无 | 少量(N问) | 充分
```

## 用户透明

一条消息说明判定与理由。用户反对「太简单」时可**上调**级别；**不得**因催促下调为 simple。
