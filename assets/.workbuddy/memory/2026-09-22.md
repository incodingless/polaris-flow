## 任务：四条工作流的上下文边界盘点（prd / coding / prototype / debug）

**结论框架（可复用判据）** —— 判断某处能否压缩/清理上下文，看三条：

1. **产物是否已落盘且能独立恢复**。`state.yaml` 只记身份与指针（`task_id` / `phase` / `output_dir`），
   进度靠产物推断 → 只要该步的产出物已落盘，历史对话即可丢。
2. **是否跨技能/跨阶段**。有 `complete-phase --next-phase X` + `update-active --set phase=X` 的位置
   天然是会话边界，且下游技能都有 Step 0 / Step 1 状态检查入口。
3. **是否带独立性要求**。评审/独立验证不得由执行者本人做 → 必须换上下文（不是「可以」）。

**两个动作要区分**：
- **压缩/清理上下文** = 同一窗口继续，丢历史留结论；**不重跑 SessionStart**。
- **新开会话** = 重跑 SessionStart，重新注入 `$PLUGIN_ROOT` / `$REPO_ROOT` / `SUPPORTS_SUBAGENT` /
  `$SUBAGENT_PROBE_CACHE`。技能里写的「清空上下文并输出 XXX」是**提示语**，技能无法自己清空上下文。
