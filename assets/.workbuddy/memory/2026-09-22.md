## 追加（第三轮）：D1 已决 —— 衔接协议落地

**用户决策**：`manual` ⇒ 输出提示，要求用户新开会话并输入对应技能名；`auto` ⇒ **必须先清空/压缩上下文，再自动执行对应技能**。

**落法**（已写入设计文档 §5.6）：这条决策把「auto 与『每技能新开会话』冲突」转成**配置约束** ——
`auto_transition` 与 `context_compression` 是同一份配置里的两个开关，默认 `true` / `off`
（`src/core/config/polaris-project-config.ts:186,190`，值域 `off | beta`）。

| auto_transition | context_compression | 行为 |
|---|---|---|
| false（建议默认） | 任意 | manual：输出提示语，停下 |
| true | beta | auto：压缩后自动执行 |
| true | off | **非法组合** → 写入时拦截 / 存量降级 manual |

**关键澄清**：「清空」与「压缩」语义不同 —— 清空会连带丢掉「下一步跑谁」（当前 agent 自己也没了），
所以 **auto 的可行实现只能是「压缩 + 立刻执行」**；真清空 = 用户新开会话 = manual 路径。
auto 执行序五步：落盘 → `state next` 算出 NEXT/SKILL → 把「下一步」与恢复清单写进落盘文件 → 压缩 → 执行。

**顺带查出的 bug**：`coding/design/SKILL.md:170` 判断 `context-compression: on`，但值域是 `off | beta` → 该分支永不命中。

**仍待定**：出厂默认值（建议 `auto_transition: false` + `context_compression: off`）。

## 追加（第四轮）：压缩动作按平台分派（推翻上一稿的一处假设）

**用户补充**：各平台压缩上下文方法不同，需按平台执行对应操作；**「清空」统一为用户新开会话**。

**查证结果（2026-09-22 联网核实，已写入设计文档 §5.6.1）**：

| 平台 | IDE | CLI | 自动压缩 |
|---|---|---|---|
| Claude Code | `/compact`（可带 focus），`/rewind` 分段摘要 | 同左 | 接近上限自动 |
| Cursor | `/summarize` | 同左 | 达上限自动摘要 |
| Trae | 上下文面板**「压缩」按钮**（仅 SOLO Agent） | `/compact` | 超窗自动 |
| Trae-CN | 同 Trae | 同 Trae | 同 Trae |
| Qoder | Smart Context Control**「压缩当前会话」按钮**（>40% 才可用；早期与生成中禁用） | `/compact`、`/clear` | — |

**推翻的假设**：上一稿写「agent 触发上下文压缩」。实际**所有平台都没把压缩交给 agent 程序化调用**——要么用户点按钮/输入斜杠命令，要么宿主在阈值自动触发；项目 `agentToolMap` 里也没有斜杠命令工具。故 **auto 只能是「半自动」**：输出本平台压缩操作提示 → 停下等用户完成压缩 → agent 自动执行下一技能（六步执行序已写入 §5.6.2）。

**新增发现（D6）**：压缩动作随 **IDE / CLI 形态**而变，而 `src/core/domain/platforms.ts` 的 `PLATFORMS` 只按平台 id 分派（claude / cursor / trae / trae-cn / qoder，字段有 `supportsSubagent` 等），**没有宿主形态维度**。压缩能力可照 `supportsSubagent` + `resolveSubagentCapability` + SessionStart 注入的既有模式扩展。
