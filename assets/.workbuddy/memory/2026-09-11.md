## P1 续：`scripts/scaffold.mjs` 落地（同日下午）

**做了什么**：薄脚手架（零依赖，~740 行）。把 §27.2「大文件编辑纪律」从纪律变成工具——给了骨架，千行级手工并行编辑的场景就不存在了。

**核心设计：4 个区域标记**，各自用所在语境的原生注释语法：
- `/* @TOKENS:BEGIN|END */`（CSS 内）、`<!-- @ICONS|NAV|PAGES:BEGIN|END -->`（HTML 内）
- `init` 生成 App Shell + Token + 20 个线性图标 symbol + 页面容器 + 路由 + 导航
- `add-page` / `add-icon` 只在区域里定点插入，**插入前断言标记唯一命中，命中数≠1 即中止且不写盘**（= §27.2 要求的断言式替换，由技能交付而非每次现写）
- `list` 总览页面/导航可达性/图标定义与引用/断链/文本 Token 对比度自检/区域标记
- 退出码 0 成功 / 1 操作失败（锚点缺失、id 重复、文件不存在）/ 2 用法错

**与 verify.mjs 的契约**（两者必须同步演进）：`section[id]` 页面容器、`data-goto` 跳转、`symbol#i-*` + `use href="#i-*"`、`--text-*` Token 命名、`window.goto()` 路由。

**实测**：init 3 页 → 全三层 PASS（3 页均 `fn:goto` 激活、visible、len≈173、三档零溢出、零运行时错误）；再 add-page×2 + add-icon×2 → 仍全 PASS（5 页）；`--flow` + `--strict` 闭环（含 2 次 data-goto 点击）退出码 0。反例：未建页面的 data-goto → L1-4 HARD；删被引用的 symbol → L1-7 HARD；破坏 @PAGES:END 后 add-page 拒绝动盘；清空 @ICONS 后可继续增长。

**踩坑（值得记）**：
1. **注释里的字面量会被 verify 当作真实引用**：初版模板注释写了 `<use href="#i-xxx"/>` 和 `goto('xxx')` 作文档说明 → 被 L1-4/L1-7 判 HARD。不是误报，是契约边界：注释里的示例语法同样被扫描。改为描述性文字。
2. **区域边界要按行首计算**：初版 `replaceRegion` 把 END 标记前的空白也吃掉，导致闭合标记缩进跑偏。改为取 END 标记行首 + 记录该行缩进。
3. **HTML 注释不能塞进 `<style>`**：`@TOKENS` 区改用 CSS 注释（`/* */`），故 region marker 需按区域可选注释语法。

**主动改的一个值（需产品确认）**：§14.3 的 `--text-placeholder:#999999` 对白底仅 ~2.8:1，违反 §14.3.1 自己的 4.5:1 硬指标，会被 L1-9 判 HARD。脚手架 Token 区改用 `#646b85`（5.27:1）。**规范正文旧值未回改**，属已知不一致，已记入 PROVENANCE 待办。

**文档接线**：SKILL.md §九（双脚本入口 + 契约警告）、§四阶段 8 后（补齐「生成」落点说明，未改阶段结构）、§十第 13–14 条；references/07 §27.2 改为「已由脚手架从根上规避 + 退回手工的禁令」；PROVENANCE 增 P1 差异 + 3 项新待办；评审文档加 7.7 + 速览现状表（5.5→7.5）。
