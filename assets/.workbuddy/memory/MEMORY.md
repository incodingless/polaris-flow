## 仓库约定（skills 层）

- **技能命名**：`name: polaris{{SKN_SPR}}<skills 下目录路径各段，用 SKN_SPR 连接>`。
  例：`zh/skills/coding/build/` → `polaris{{SKN_SPR}}coding{{SKN_SPR}}build`。
  **name 后缀必须与目录名一致**（`generate-prototype/` → `polaris{{SKN_SPR}}generate-prototype`）。
- **frontmatter 字段**：所有技能只用标准 `description` 字段（≤1024 字符）。
  **禁止**引入 `description_zh` / `description_en` / `display_name` / `display_name_en`（那是市场技能的形态）。
- 技能目录内可放 `PROVENANCE.md` 记录来源与许可；`license` 未核实前不填、不臆造。
- **SKILL.md 分层约定**：**路由信息（触发词、不触发边界）只写 `description`；执行信息只写正文**。
  判据是「这条信息在哪个时刻被读才起作用」——路由时刻读的写 description，执行时刻读的留正文。
  正文里不放「何时使用」类任务枚举（触发发生在正文加载之前，"进门后才看门牌"）；反过来，
  执行期纪律（如「不替产品经理决定范围与实现深度」）**不得**写进 description——那是路由层，读完就走。

  - `scripts/verify.mjs` —— §27.1 三层验证的执行体。

    机制：4 个区域标记（CSS 用 `/* @TOKENS */`，HTML 用 `<!-- @ICONS|NAV|PAGES -->`）圈出可增长部分；

## HTML 原型验证的通用手法（可复用于 lofi-prototype 等）

免装 Playwright：用系统 Chrome/Edge/Chromium + `--headless=new --dump-dom --virtual-time-budget=4000 --window-size=W,H`，
**探针注入原型同目录副本**（保证相对资源可解析），结果写入带 id 的渲染锚点元素（如 `<pre id="__pvResult">`）后按元素提取——
不要用全文正则，会命中探针自身源码。错误采集器必须**早于作者脚本**注入（charset 声明之后），否则采不到加载期抛错。

## 工具教训

**核验/批量改中文内容不要用 macOS 的 grep**：BSD grep 在双引号里**不吃 `\|` 交替**，`grep -rn "33\.5\|33\.6"` 会静默返回空，
容易被误读成「没有引用」；中文多字节模式也不可靠（`'9 个阶段'` 明明存在却匹配不到）。
扫描一律用 ripgrep（Grep 工具），或 `grep -E 'a|b'`、分开写。

**本机 fs 删除被守卫**：`node-safe-delete-shim.cjs` 会统计**每轮 turn 的删除数，超过 50 直接抛错**
（`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`）。清理临时文件别一次删太多，
也别把这种「删太多」误判成脚本 bug——脚本侧的清理一律写成 `try/catch`（如 verify 的 `safeRemove()`）。

**改含 template literal 的脚本时，注释里别用反引号包标识符**：反引号会截断模板字符串，报 `SyntaxError` 且报错位置误导。
