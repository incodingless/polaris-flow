## 原型族触发语义重构（blueprint 吃总目标 / build 收窄接续）+ build 完成后暂停

**用户拍板的两件事**：①"制作原型"归 blueprint（链首），build 收窄为接续与返工语义；
② **build 完成后暂停等用户确认，不自动推进 ship**（避免原型没看就被归档）。

**为什么不能只是"把制作原型搬进 blueprint"**：该词原本正是 build 的主触发词，直接搬=两个技能抢同一句话。
**正确分法**：blueprint 吃**总目标语义**（做个原型 / 从需求到原型交付 / 这个需求要做哪些页面），
build 吃**接续语义**（照蓝图做 / 蓝图确认了开始做 / 继续做原型 / 重做某几个页面 / 修改已有原型）。
**触发词分不开的意图交给状态分**——blueprint Step 1.5 补一行
「`blueprint.status == confirmed` → 不再重跑本技能，引导到 build」（原表对已确认蓝图落到「无法判定」，是真空）。

**修掉一个互相推诿的真空**：`build` 写「不触发：修改已有原型」、`review` 写「修改原型走 build」——
两边互推，"改一个已有原型"没人接。已归口 build。**归口后立刻暴露第二个缺口**：
